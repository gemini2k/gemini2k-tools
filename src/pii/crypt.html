텍스트 암호화 / 복호화

비밀번호로 메모·메시지를 AES-256으로 잠그고 풉니다. 암호화된 결과만 안전한 곳에 보관하거나 전달하세요. 모든 처리는 이 브라우저 안에서만 이루어집니다.

📖
사용 방법
  1. 위에서 '암호화' 또는 '복호화'를 고릅니다
  2. 내용과 비밀번호를 입력합니다 (비밀번호는 꼭 따로 보관하세요)
  3. 실행 버튼을 누르고 결과를 복사합니다
↓
비밀번호를 잊으면 복구할 수 없습니다. AES-256-GCM으로 암호화하고, 비밀번호는 PBKDF2-SHA256(15만 회)로 키를 유도합니다. 결과 Base64에는 솔트(16B) + IV(12B) + 암호문이 함께 담겨 있어, 같은 비밀번호만 있으면 어디서든 복호화됩니다. 비밀번호·평문·암호문 모두 서버로 전송되지 않습니다.

텍스트 암호화·복호화 도구 사용 안내

무엇을 하는 도구인가

입력한 비밀번호로 짧은 텍스트를 잠그고 푸는 도구입니다. 비밀번호를 그대로 키로 쓰지 않고, 무작위 솔트 16바이트와 함께 PBKDF2-SHA256을 15만 회 돌려 256비트 키를 만든 뒤 AES-256-GCM으로 암호화합니다. 결과는 솔트(16B) + IV(12B) + 암호문을 이어 붙여 Base64 한 줄로 내보내므로, 이 한 줄과 비밀번호만 있으면 다른 기기에서도 복호화할 수 있습니다.

솔트와 IV를 매번 새로 뽑기 때문에 같은 문장을 같은 비밀번호로 두 번 암호화해도 결과가 다르게 나옵니다. 정상 동작입니다.

언제 쓰나

  • 서버 접속 정보나 임시 계정 비밀번호를 메신저·메일로 넘겨야 할 때, 본문은 암호문으로 보내고 비밀번호는 전화 등 다른 경로로 알려 줄 때
  • 업무 메모 중 일부(연락처, 계좌 등)를 공유 문서에 남겨야 하는데 열람자를 제한하고 싶을 때
  • 개발 중 설정값을 잠깐 보관하거나, AES-GCM 결과 형식을 확인해 보고 싶을 때

사용 방법

  1. 위쪽에서 「암호화」 또는 「복호화」를 고릅니다. 모드를 바꾸면 입력·결과 칸이 비워집니다.
  2. 암호화는 평문을, 복호화는 Base64 암호문을 입력 칸에 넣습니다.
  3. 비밀번호를 입력합니다. 눈 모양 버튼으로 입력값을 확인할 수 있습니다.
  4. 실행 버튼을 누르고 「결과 복사」로 가져갑니다.

결과 해석

예를 들어 「회의실 비밀번호 4821」을 암호화하면 수십 자 길이의 영문·숫자·+ / = 조합이 나옵니다. 앞부분 28바이트는 솔트와 IV라서 짧은 평문이라도 결과가 꽤 깁니다. 복호화 때 「복호화 실패」가 나오면 비밀번호가 틀렸거나 암호문이 한 글자라도 잘렸다는 뜻입니다. GCM은 무결성 검사를 함께 하므로 변조된 암호문은 엉뚱한 글자 대신 실패로 끝납니다.

주의할 점

  • 비밀번호를 잊으면 되살릴 방법이 없습니다. 이 사이트에도 아무것도 저장되지 않습니다.
  • 보안 수준은 결국 비밀번호에 달려 있습니다. 짧거나 흔한 비밀번호는 PBKDF2를 거쳐도 대입 공격에 버티기 어렵습니다.
  • 암호문과 비밀번호를 같은 메일·같은 대화방에 함께 보내면 암호화한 의미가 없습니다.
  • 이 형식은 이 도구 전용입니다. 다른 프로그램에서 풀려면 같은 구조(솔트·IV 위치, 반복 횟수)를 맞춰 구현해야 합니다.
  • 법령이 요구하는 개인정보 암호화(저장·전송 구간의 암호화 조치)를 대신하는 도구는 아닙니다. 개인 메모나 일회성 전달용으로 쓰세요.

자주 묻는 질문

입력한 내용이 서버로 가지 않나요?
네. 암호화와 복호화는 브라우저의 Web Crypto API로 처리되고, 평문·비밀번호·암호문을 전송하는 코드는 없습니다.
같은 내용을 다시 암호화했더니 결과가 달라요.
솔트와 IV를 매번 무작위로 만들기 때문입니다. 어느 결과든 같은 비밀번호로 똑같이 복호화됩니다.
파일도 암호화할 수 있나요?
이 도구는 텍스트 전용입니다. 파일은 텍스트로 바꾸지 않는 한 넣을 수 없습니다.
