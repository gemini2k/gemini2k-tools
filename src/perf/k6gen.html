k6 / JMeter 부하 스크립트 생성기

대상·부하 조건을 입력하면 k6(JS)와 JMeter(.jmx) 부하시험 스크립트를 만들어 줍니다.

요청 본문(Body) · POST/PUT용 — 선택
생성된 스크립트는 외부로 전송되지 않고 브라우저에서만 만들어집니다. 실제 부하 발생은 내려받은 스크립트를 k6 또는 Apache JMeter로 본인이 권한을 가진 대상에 대해서만 실행하세요. p95<500ms·실패율<1% 임계값이 예시로 포함됩니다.

k6 / JMeter 부하 스크립트 생성기 사용 안내

무엇을 하는 도구인가

대상 URL, 메서드, 가상사용자(VU) 수, 지속 시간, 램프업, 생각 시간(think time)을 입력하면 같은 조건의 부하시험 스크립트를 두 형식으로 만들어 줍니다. k6용은 k6/http 모듈을 쓰는 JavaScript 파일이고, JMeter용은 Thread Group 하나와 HTTP 요청 샘플러 하나로 이루어진 .jmx 테스트 계획입니다. 도구는 스크립트만 만들 뿐 실제 요청은 보내지 않습니다.

언제 쓰나

  • 신규 API 오픈 전에 기본적인 부하 시나리오의 뼈대를 빠르게 잡을 때
  • k6나 JMeter를 처음 써 보는 팀원에게 최소 구성 예제를 건넬 때
  • 같은 조건을 두 도구로 돌려 결과를 비교해 보고 싶을 때

사용 방법

  1. 「대상 URL」과 「메서드」를 정하고, 「VU(가상사용자)」, 「지속(초)」, 「Ramp-up(초)」, 「Think time(초)」을 입력합니다.
  2. POST·PUT이면 「요청 본문(Body)」을 펼쳐 JSON을 넣습니다.
  3. 「k6 (JS)」 또는 「JMeter (.jmx)」를 고르면 아래 칸에 스크립트가 바로 갱신됩니다.
  4. 「복사」나 「다운로드」(loadtest.js 또는 loadtest.jmx)로 가져가 k6 run loadtest.js 또는 jmeter -n -t loadtest.jmx -l result.jtl로 실행합니다.

결과 해석

k6 스크립트의 options.stages는 램프업이 0보다 크면 「램프업 동안 VU까지 증가 → 지속 시간 유지 → 램프업과 같은 시간 동안 0으로 감소」의 3단계입니다. 기본값(VU 50, 지속 60초, 램프업 10초)이면 k6는 총 80초 돕니다. JMeter 쪽은 스레드 50개, 램프업 10초, 스케줄러 지속 60초, 반복 무한으로 들어가며, 지속 시간이 램프업을 포함한 전체 실행 시간이라 약 60초 후 끝납니다. 숫자가 같아도 두 도구의 총 부하량이 다르다는 점을 감안하세요. k6에는 p(95)<500ms, 실패율 rate<0.01 임계값과 상태코드 200 확인이 예시로 들어 있습니다.

주의할 점

  • 부하시험은 본인이 운영하거나 허락받은 서버에만 하세요. 남의 서비스에 부하를 주면 업무 방해가 될 수 있습니다.
  • 본문이 있는 POST·PUT 요청에는 k6와 JMeter 모두 Content-Type: application/json 헤더가 들어갑니다(JMeter는 요청 아래 HTTP Header Manager로 추가). 폼 데이터나 XML을 보낸다면 이 값을 맞게 고치세요.
  • 임계값과 200 확인은 예시입니다. 201·204를 돌려주는 API라면 check 조건과 목표 응답시간을 서비스 기준에 맞게 고치세요.
  • 로그인 토큰, 여러 단계의 사용자 흐름, 테스트 데이터 변수화는 생성되지 않으므로 직접 추가해야 합니다.

자주 묻는 질문

VU 50이면 초당 50건 요청인가요?
아닙니다. VU는 동시에 도는 사용자 수이고, 초당 요청 수는 응답시간과 생각 시간에 따라 달라집니다. 응답이 0.2초, 생각 시간이 1초면 VU 하나가 대략 1.2초에 한 번 요청합니다.
입력한 URL이 어딘가로 전송되나요?
아닙니다. 스크립트 문자열은 브라우저에서만 만들어집니다.
