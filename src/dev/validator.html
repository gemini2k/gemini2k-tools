문자열 유효성 검사기

입력한 값이 어떤 형식으로 유효한지 한 번에 확인합니다.

형식유효 여부
오픈소스 validator.js(MIT, validatorjs/validator.js)를 자체 호스팅합니다. 모든 처리는 브라우저에서만 이루어집니다.

문자열 유효성 검사기 사용 안내

무엇을 하는 도구인가

입력한 값 하나를 validator.js 13의 검사 함수 16가지에 동시에 넣어, 어떤 형식으로 유효한지를 표로 보여 줍니다. 검사 항목은 이메일, URL, IPv4, IPv6, 신용카드, UUID, JSON, 숫자만, 영문/숫자, 16진수 색상, 날짜(ISO), JWT, Base64, MAC 주소, 휴대폰(ko), 우편번호(ko)입니다. 휴대폰과 우편번호는 한국 형식 규칙을 씁니다. 각 함수는 기본 옵션 그대로 호출합니다.

언제 쓰나

  • 회원가입·주문 폼의 입력 검증 규칙을 정하기 전에 경계값이 통과하는지 미리 볼 때
  • 서버에서 validator.js를 쓰고 있는데 특정 값이 왜 거부되는지 확인할 때
  • 엑셀로 받은 이메일·전화번호 중 형식이 이상한 값을 하나씩 확인할 때
  • 정체를 모르는 문자열이 UUID인지, JWT인지, Base64인지 감을 잡을 때

사용 방법

  1. 입력란에 검사할 값을 하나 넣습니다. 처음에는 hello@example.com이 들어 있습니다.
  2. 표의 「유효 여부」 열에서 ✓ 표시가 붙은 형식을 확인합니다. 입력을 바꾸는 즉시 다시 검사합니다.

결과 해석

여러 항목에 동시에 ✓가 붙는 것이 정상입니다. 기본값 hello@example.com은 이메일뿐 아니라 URL에도 ✓가 붙는데, URL 검사가 프로토콜 없는 주소와 사용자@호스트 형태를 허용하기 때문입니다. abcd는 Base64, 영문/숫자, 16진수 색상(# 없이 4자리) 세 곳에서 통과합니다. 01012345678은 숫자만, 영문/숫자, 휴대폰(ko)에 ✓가 붙고, 010-1234-5678처럼 하이픈을 넣으면 휴대폰(ko)만 남습니다. 신용카드는 자릿수와 룬(Luhn) 검사합을 보므로 4111111111111111 같은 테스트 번호도 통과합니다.

주의할 점

  • 형식만 검사합니다. 이메일이 실제로 수신 가능한지, 카드가 발급된 번호인지는 알 수 없습니다.
  • 앞뒤 공백을 자동으로 지우지 않아 a@b.com처럼 공백이 섞이면 실패합니다.
  • JSON 검사는 객체나 배열만 유효로 보므로 123 같은 단독 숫자는 —로 나옵니다. 우편번호(ko)는 다섯 자리 숫자 형식입니다.
  • 실제 카드 번호는 넣지 마세요. 검사는 브라우저에서만 이루어지지만 화면 공유나 기록에 남을 수 있습니다.

자주 묻는 질문

이 화면에서는 기본 옵션만 씁니다. 서버 코드에서 옵션을 다르게 주었다면 결과가 다를 수 있습니다.
값이 서버로 전송되나요?
아닙니다. validator.js를 브라우저에서 실행해 검사합니다.
