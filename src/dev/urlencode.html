URL 인코딩 / 디코딩

URL·쿼리 문자열의 한글·특수문자·공백을 퍼센트 인코딩하거나, 인코딩된 주소를 사람이 읽을 수 있게 디코딩합니다.

↓
구성요소는 쿼리 값·경로 조각처럼 부분 문자열에 쓰며 ?&=/:# 등도 모두 인코딩합니다. 전체 URL은 주소 전체를 인코딩하되 :/?#&= 등 URL 구조 문자는 보존합니다. 입력·결과는 서버로 전송되지 않습니다.

URL 인코딩 / 디코딩 사용 안내

무엇을 하는 도구인가

문자열을 UTF-8 바이트로 바꾼 뒤 URL에 그대로 쓸 수 없는 글자를 %XX 형태로 바꾸는 퍼센트 인코딩과, 그 반대인 디코딩을 합니다. 브라우저 내장 함수를 그대로 쓰며, 「구성요소」를 고르면 encodeURIComponent/decodeURIComponent, 「전체 URL」을 고르면 encodeURI/decodeURI로 처리합니다. 두 방식은 어떤 기호를 남겨 두느냐가 다릅니다.

언제 쓰나

  • 검색어나 파일명 같은 한글 값을 쿼리 문자열에 넣는 링크를 직접 만들 때
  • 접속 로그나 리퍼러에 %ED%95%9C…처럼 찍힌 주소를 읽을 수 있게 풀 때
  • API 테스트 중 파라미터 값에 &, =, +가 들어가 요청이 깨지는 원인을 찾을 때
  • 리디렉션 URL을 다른 URL의 파라미터로 넘겨야 할 때

사용 방법

  1. 「입력」에 문자열이나 주소를 붙여 넣습니다.
  2. 값 하나만 바꿀 때는 「구성요소 (encodeURIComponent)」, 주소 전체를 다룰 때는 「전체 URL (encodeURI)」을 고릅니다.
  3. 「인코딩 ↓」 또는 「디코딩 ↓」을 누르면 「결과」에 나옵니다.
  4. 결과를 다시 처리하려면 「⇅ 입력↔출력」으로 결과를 입력란으로 옮깁니다. 「결과 복사」로 가져갑니다.

결과 해석

「한글 검색」을 구성요소 방식으로 인코딩하면 %ED%95%9C%EA%B8%80%20%EA%B2%80%EC%83%89이 됩니다. 한글 한 글자는 UTF-8로 3바이트라 %XX 세 개가 되고, 공백은 %20이 됩니다. https://example.com/검색?q=한글 검색어&page=1을 전체 URL 방식으로 인코딩하면 한글과 공백만 바뀌고 ://, ?, &, =은 그대로 남습니다. 같은 주소를 구성요소 방식으로 인코딩하면 이 구조 문자까지 모두 바뀌어 더는 주소로 동작하지 않습니다.

주의할 점

  • 파라미터 값 안에 &나 =가 들어 있으면 전체 URL 방식으로는 인코딩되지 않습니다. 값만 따로 구성요소 방식으로 인코딩해서 끼워 넣으세요.
  • HTML 폼 전송처럼 공백을 +로 표시한 값은 디코딩해도 +가 공백으로 바뀌지 않습니다. 먼저 +를 %20으로 바꾼 뒤 디코딩하세요.
  • 이미 인코딩된 문자열을 다시 인코딩하면 %가 %25로 바뀌는 이중 인코딩이 됩니다. 결과에 %25가 보이면 한 번 더 디코딩해 보세요.
  • % 뒤 두 자리가 올바른 16진수가 아니거나 UTF-8 바이트 순서가 깨진 문자열은 디코딩 오류가 납니다. EUC-KR로 인코딩된 옛 주소가 대표적입니다.
