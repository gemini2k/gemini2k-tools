ULID 생성기

시간순으로 정렬되는 26자 고유 ID(ULID)를 만듭니다. UUID 대신 정렬·가독성이 필요할 때 좋아요.

ULID = 48비트 타임스탬프(밀리초) + 80비트 난수, Crockford Base32 26자. 같은 밀리초에 만든 ID는 난수 부분을 1씩 늘려(단조 증가) 생성 순서대로 정렬됩니다. 난수는 암호학적(crypto)입니다. 모든 처리는 브라우저에서만 이루어집니다.

ULID 생성기 사용 안내

무엇을 하는 도구인가

ULID(Universally Unique Lexicographically Sortable Identifier) 형식의 26자 ID를 1~100개 만듭니다. 앞 10자는 현재 시각을 밀리초 단위 48비트로, 뒤 16자는 브라우저의 암호학적 난수(crypto.getRandomValues) 80비트를 Crockford Base32로 적은 것입니다. Crockford Base32는 숫자 0~9와 알파벳 중 헷갈리기 쉬운 I, L, O, U를 뺀 32글자만 씁니다.

언제 쓰나

  • DB 기본키로 만든 순서대로 정렬되는 ID가 필요하지만 자동 증가 숫자는 노출하고 싶지 않을 때
  • 로그나 이벤트 ID만 보고도 대략 언제 생긴 것인지 알고 싶을 때
  • UUID v4를 키로 쓰다가 인덱스 단편화가 신경 쓰여 시간순 ID와 비교해 볼 때
  • 테스트 데이터나 픽스처에 넣을 ULID 샘플이 필요할 때

사용 방법

  1. 「개수」에 1~100 사이 숫자를 넣습니다.
  2. 「🔄 생성」을 누르면 한 줄에 하나씩 ULID가 나옵니다. 페이지를 열 때도 한 번 만들어집니다.
  3. 「복사」로 목록 전체를 줄바꿈으로 구분해 가져갑니다.

결과 해석

ULID 명세의 예시인 01ARZ3NDEKTSV4RRFFQ69G5FAV로 보면 01ARZ3NDEK가 시각, TSV4RRFFQ69G5FAV가 난수입니다. 시각 부분이 앞에 있으므로 문자열 정렬만으로 생성 시각 순서가 맞춰지고, 첫 글자는 48비트 범위 때문에 항상 0~7 중 하나입니다. 이 도구는 버튼을 한 번 누를 때 시각을 한 번만 읽으므로, 같이 만든 ID들은 앞 10자가 모두 같고 뒤 16자는 첫 값에서 1씩 커집니다.

주의할 점

  • 같은 밀리초에 만든 ID는 명세의 단조 증가(monotonic) 방식대로 첫 ID의 난수에 1씩 더해 만듭니다. 그래서 한 번에 만든 여러 개는 화면에 나온 순서와 정렬 순서가 같지만, 뒤 16자가 연속된 값이라 서로 추측하기 쉽습니다. 다른 ID를 짐작할 수 없어야 하는 용도라면 한 번에 하나씩 만드세요.
  • ID에 생성 시각이 그대로 드러납니다. 가입 시각처럼 감춰야 할 정보가 추정되면 곤란한 곳에는 UUID v4가 낫습니다.
  • DB에 저장할 때는 26자 문자열 그대로 넣거나, 16바이트 이진값으로 바꿔 넣는 방식 중 하나로 통일하세요.

자주 묻는 질문

소문자로 써도 같은 ID인가요?
ULID 명세상 대소문자를 구분하지 않으므로 같은 값으로 취급하지만, 이 도구는 대문자로만 출력합니다.
