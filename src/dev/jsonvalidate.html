JSON 스키마 검증기

JSON 데이터가 JSON Schema(draft-07) 규칙에 맞는지 확인하고, 어긋난 부분을 알려 줍니다.

오픈소스 Ajv(MIT, ajv-validator/ajv)를 자체 호스팅합니다. 이메일·날짜 등 format 검증과 draft-07 스키마를 지원합니다. 모든 처리는 브라우저에서만 이루어집니다.

JSON 스키마 검증기 사용 안내

무엇을 하는 도구인가

JSON Schema와 데이터를 나란히 넣으면 Ajv 6으로 스키마를 컴파일해 데이터가 규칙에 맞는지 검사하고, 어긋난 곳을 경로와 메시지로 모두 나열합니다. 첫 오류에서 멈추지 않고 전체 오류를 모으며(allErrors), email, date, uri 같은 format 키워드도 엄격한 full 모드로 검사합니다. 지원하는 스키마 버전은 draft-07(및 draft-06)입니다.

언제 쓰나

  • API 요청 본문이 명세의 스키마를 통과하는지 서버에 보내기 전에 확인할 때
  • 새로 쓴 스키마가 의도대로 잘못된 데이터를 걸러 내는지 일부러 틀린 예시로 시험할 때
  • 설정 파일 검증 오류가 났을 때 어느 필드가 문제인지 찾을 때

사용 방법

  1. 왼쪽 'JSON Schema'에 스키마를, 오른쪽 '검증할 데이터'에 데이터를 넣습니다.
  2. 입력하는 즉시 검사되며, [검증하기]로 다시 실행할 수도 있습니다.
  3. 통과하면 초록 안내가, 실패하면 위반 개수와 목록이 나옵니다.

결과 해석

기본 예시는 2건 위반으로 나옵니다. .age — should be >= 0은 age가 minimum: 0을 어겼다는 뜻이고, .email — should match format "email"은 이메일 형식이 아니라는 뜻입니다. 앞의 경로는 데이터 안 위치를 .items[0].id처럼 표시하며, 필수 키가 빠진 경우처럼 객체 전체에 대한 오류는 (root)로 나옵니다. 예를 들어 데이터에서 name을 지우면 (root) — should have required property 'name'이 추가됩니다. 메시지는 Ajv가 내는 영어 원문입니다.

주의할 점

Ajv 6이라 "$schema"에 draft 2019-09나 2020-12 주소, 또는 draft-04 주소를 적으면 해당 메타스키마가 없다는 스키마 정의 오류가 납니다. 이때는 $schema 줄을 지우거나 draft-07 주소로 바꿔 보세요. 다만 2020-12 전용 키워드(prefixItems, $defs 참조 방식 차이 등)는 draft-07에서 다르게 동작하거나 무시될 수 있습니다. 외부 URL로 된 $ref는 내려받지 않으므로 해석되지 않습니다.

자주 묻는 질문

스키마가 없는데 검증하고 싶어요.
JSON 스키마 생성기로 예시 데이터에서 초안을 만든 뒤 여기 붙여넣고 다듬으면 됩니다.
스키마에 없는 키가 있는데 통과돼요.
JSON Schema는 기본적으로 정의되지 않은 키를 허용합니다. 막으려면 객체에 "additionalProperties": false를 추가하세요.
