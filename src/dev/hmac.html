HMAC 생성기

비밀 키로 메시지의 HMAC 값을 만듭니다. API 요청 서명, 웹훅 검증, 무결성 확인에 쓰세요.

표준 HMAC을 브라우저의 Web Crypto로 계산합니다. 키·메시지는 UTF-8로 처리하며 결과는 16진수입니다. 비밀 키와 메시지는 서버로 전송되지 않습니다.

HMAC 생성기 사용 안내

무엇을 하는 도구인가

비밀 키와 메시지로 RFC 2104 방식의 HMAC(키 기반 메시지 인증 코드)을 계산합니다. 키와 메시지는 UTF-8 바이트로 바꾸어 브라우저 내장 Web Crypto API에 넘기며, 해시 함수는 SHA-256, SHA-1, SHA-384, SHA-512 중에서 고를 수 있습니다. 결과는 소문자 16진수로 표시됩니다.

언제 쓰나

  • GitHub·Stripe·Slack 같은 서비스의 웹훅 서명 검증 코드가 맞게 계산하는지 손으로 대조할 때
  • 사내 API의 요청 서명(타임스탬프+본문 서명) 규격을 구현하면서 기대값을 만들 때
  • 서명 불일치 오류가 났을 때 키나 메시지 중 무엇이 달라졌는지 하나씩 바꿔 가며 확인할 때

사용 방법

  1. '메시지'에 서명할 원문을 넣습니다. 웹훅이라면 요청 본문을 가공 없이 그대로 넣어야 합니다.
  2. '비밀 키 (Secret)'에 공유 키를 넣습니다.
  3. '해시 알고리즘'을 고르면 '결과 (HEX)'가 자동으로 갱신됩니다. [HMAC 생성]으로 다시 계산할 수도 있습니다.
  4. [📋 복사]로 결과를 가져갑니다.

결과 해석

기본값인 메시지 hello, 키 secret, SHA-256의 결과는 88aab3ede8d3adf94d26ab90d3bafd4a2083070c3bcce9c014ee04a443847c0b입니다. SHA-1로 바꾸면 5112055c05f944f85755efc5cd8970e194e9f45b가 됩니다. GitHub 웹훅의 X-Hub-Signature-256 헤더는 sha256= 뒤에 이 16진수 값이 붙은 형식이므로 접두어를 떼고 비교하면 됩니다.

주의할 점

키는 텍스트로만 받습니다. AWS 서명 v4의 중간 단계 키처럼 바이너리 키나, Base64로 주어진 키를 디코딩해 써야 하는 규격은 이 도구로 그대로 재현되지 않습니다. 결과도 16진수만 나오므로 Base64 서명을 쓰는 서비스(예: Shopify 웹훅)는 별도 변환이 필요합니다. 메시지 끝의 줄바꿈 하나, JSON 공백 하나만 달라도 값이 바뀝니다. 실제 서비스 키는 입력 후 페이지를 닫아 두세요.

자주 묻는 질문

HMAC과 그냥 해시는 무엇이 다른가요?
해시는 누구나 계산할 수 있지만 HMAC은 키를 아는 쪽만 같은 값을 만들 수 있어, 메시지가 위조되지 않았음을 확인하는 데 씁니다.
서명 값을 비교할 때 주의할 점은요?
서버 코드에서는 일반 문자열 비교 대신 상수 시간 비교 함수(예: Node의 timingSafeEqual)를 써야 타이밍 공격을 피할 수 있습니다.
