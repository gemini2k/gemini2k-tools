UUID 생성기 (v4)

암호학적 난수로 UUID 버전 4를 한 번에 여러 개 만듭니다. 개발·테스트 데이터의 고유 식별자로 쓰세요.

UUID v4는 122비트 난수로 만들어져 사실상 중복되지 않는 식별자입니다. 이 도구는 브라우저의 암호학적 난수 생성기(crypto)를 사용하며, 생성된 값은 서버로 전송되지 않습니다.

UUID 생성기(v4) 사용 안내

무엇을 하는 도구인가

RFC 9562(이전 RFC 4122)에 정의된 UUID 버전 4를 한 번에 1~100개 만듭니다. 브라우저가 제공하는 crypto.randomUUID()를 쓰고, 이를 지원하지 않는 브라우저에서는 crypto.getRandomValues()로 16바이트 난수를 받아 버전·변형 비트를 직접 맞춥니다. 두 경우 모두 암호학적 난수 생성기를 쓰므로 Math.random 기반 생성기보다 예측하기 어렵습니다.

언제 쓰나

  • DB 레코드나 업로드 파일 이름에 겹치지 않는 식별자를 붙일 때
  • API 테스트에서 요청 ID, 멱등성 키(Idempotency-Key)가 필요할 때
  • 설정 파일이나 픽스처에 고유 ID 몇 개를 손으로 넣어야 할 때
  • 여러 서버에서 중앙 발급 없이 ID를 만들어야 하는 구조를 시험할 때

사용 방법

  1. 「개수」에 1~100 사이 숫자를 넣고 「새로 생성」을 누릅니다. 페이지를 열 때도 5개가 만들어집니다.
  2. 필요하면 「대문자」, 「하이픈 제거」를 체크합니다. 이미 만든 목록에도 바로 적용됩니다.
  3. 각 줄의 「복사」로 하나씩, 「전체 복사」로 목록 전체를 줄바꿈으로 구분해 가져갑니다.

결과 해석

결과는 xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx 모양의 36자(하이픈 4개 포함)입니다. 셋째 덩어리 첫 글자는 항상 버전을 뜻하는 4이고, 넷째 덩어리 첫 글자 y는 변형(variant) 비트 때문에 8, 9, a, b 중 하나입니다. 128비트 중 이 6비트를 뺀 122비트가 난수입니다. 「하이픈 제거」를 켜면 32자 16진수만 남는데, 값 자체는 같고 표기만 다릅니다.

주의할 점

  • v4는 무작위라 생성 순서대로 정렬되지 않습니다. DB 기본키로 쓰면 삽입 위치가 흩어져 인덱스 효율이 떨어질 수 있으니, 정렬이 필요하면 UUID v7이나 ULID를 검토하세요. 이 도구는 v4만 만듭니다.
  • UUID는 추측하기 어려울 뿐 비밀번호나 인증 토큰을 대신하도록 설계된 값이 아닙니다.
  • 시스템마다 대소문자를 구분해 비교하는 경우가 있으니 한 시스템 안에서는 표기를 통일하세요.

자주 묻는 질문

중복될 가능성은 없나요?
이론상 0은 아니지만 2의 122제곱 가지 중에서 무작위로 고르므로, 일반적인 서비스 규모에서는 중복을 걱정하지 않아도 되는 수준입니다.
GUID와 같은 건가요?
마이크로소프트 환경에서 부르는 GUID도 같은 형식입니다. 다만 일부 도구는 중괄호를 붙인 {…} 형태로 쓰므로 필요하면 직접 감싸세요.
