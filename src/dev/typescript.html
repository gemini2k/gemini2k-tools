TypeScript → JavaScript

TypeScript 코드를 JavaScript로 컴파일해 결과를 보여 줍니다.

타깃 모듈
컴파일 중…
오픈소스 TypeScript(Apache-2.0, microsoft/TypeScript)를 자체 호스팅합니다. 타입 검사 오류는 표시하지 않고 변환만 수행합니다(transpile). 모든 처리는 브라우저에서만 이루어집니다.

TypeScript → JavaScript 변환 사용 안내

무엇을 하는 도구인가

TypeScript 5 컴파일러의 transpileModule 기능으로 TS 코드를 JavaScript로 바꿉니다. 인터페이스·타입 별칭·타입 표기를 지우고, enum이나 네임스페이스처럼 실행 코드가 필요한 문법은 그에 맞는 JS로 펼칩니다. 「타깃」에서 어느 버전의 JS 문법으로 낮출지, 「모듈」에서 import/export를 어떤 형식으로 바꿀지 고를 수 있습니다. 입력하다 잠시 멈추면(약 0.35초) 결과가 다시 만들어집니다.

언제 쓰나

  • TS로 된 예제 코드를 빌드 설정이 없는 JS 프로젝트나 브라우저 콘솔에서 바로 써야 할 때
  • enum이나 생성자 매개변수 속성(constructor(private name: string))이 실제로 어떤 JS가 되는지 확인할 때
  • ES5처럼 오래된 런타임을 지원해야 할 때 템플릿 문자열·화살표 함수가 어떻게 바뀌는지 볼 때
  • tsconfig의 target·module 설정이 출력에 주는 차이를 비교할 때

사용 방법

  1. 왼쪽 「TypeScript」 칸에 코드를 붙여 넣습니다.
  2. 「타깃」(ESNext·ES2020·ES2017·ES2015·ES5, 기본 ES2017)과 「모듈」(ESNext·CommonJS·None, 기본 CommonJS)을 고릅니다.
  3. 오른쪽 「JavaScript 출력」을 확인하고 「복사」를 누릅니다.

결과 해석

기본 예제를 ES2017로 바꾸면 interface User 선언이 통째로 사라지고 greet(user: User): string은 greet(user)가 되며 나머지는 거의 그대로입니다. 타깃을 ES5로 바꾸면 const가 var로, 화살표 함수가 function (u) { return greet(u); }로, 템플릿 문자열이 "Hello, ".concat(…) 형태로 바뀝니다. enum Color { Red, Green }은 숫자와 이름을 양방향으로 찾는 객체를 만드는 즉시 실행 함수로 펼쳐집니다.

주의할 점

  • 타입 검사를 하지 않습니다. const x: number = "a";처럼 타입이 틀린 코드도 오류 없이 변환됩니다. 타입 오류 확인은 tsc나 편집기에서 해야 합니다.
  • 파일 하나씩 따로 변환하므로 다른 파일의 타입 정보가 필요한 기능(예: 다른 파일의 const enum 값 인라인)은 기대대로 동작하지 않을 수 있습니다.
  • ES5 타깃은 문법만 낮출 뿐 Promise, Map 같은 내장 객체를 채워 주지 않습니다. 오래된 브라우저에서는 폴리필이 따로 필요합니다.

자주 묻는 질문

출력 들여쓰기가 4칸인데 바꿀 수 있나요?
TypeScript 컴파일러가 출력하는 형식이라 이 화면에서는 바꿀 수 없습니다. 필요하면 결과를 Prettier 같은 포매터로 다시 정리하세요.
코드가 서버로 전송되나요?
아닙니다. 컴파일러 파일을 받아 브라우저 안에서만 변환합니다.
