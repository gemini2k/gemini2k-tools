LZ-String 압축기

긴 텍스트·JSON을 짧은 문자열로 압축합니다. URL 파라미터나 localStorage에 담기 좋아요.

방식
↓
오픈소스 LZ-String(MIT, pieroxy/lz-string)을 자체 호스팅합니다. 압축·해제 방식은 양쪽이 같아야 합니다. 모든 처리는 브라우저에서만 이루어집니다.

LZ-String 압축기 사용 안내

무엇을 하는 도구인가

LZ-String 라이브러리로 텍스트를 압축해 짧은 문자열로 바꾸거나, 그렇게 만든 문자열을 원문으로 되돌립니다. 「압축」「해제」로 방향을 고르고, 「방식」에서 결과에 쓸 문자 집합(URL용·Base64·UTF16)을 정합니다. 입력이 바뀔 때마다 결과가 바로 갱신됩니다. 결과물은 gzip이나 zip 파일과 형식이 달라 서로 풀 수 없습니다.

언제 쓰나

  • 웹 앱의 필터 조건이나 편집 상태(JSON)를 URL 해시에 담아 공유 링크로 만들 때
  • 프런트엔드 코드가 주소창이나 localStorage에 남긴 LZ-String 값을 풀어 내용을 확인할 때
  • 큰 JSON을 localStorage에 넣기 전에 실제로 얼마나 줄어드는지 가늠할 때
  • 버그 신고로 받은 공유 링크 안의 상태 값을 꺼내 재현할 때

사용 방법

  1. 「압축」 또는 「해제」를 누릅니다.
  2. 「방식」을 고릅니다. 주소에 넣을 값이면 「URL용(UTF-safe)」, 텍스트로 주고받을 값이면 「Base64」, 브라우저 저장소에 넣을 값이면 「UTF16(최소크기)」가 맞습니다.
  3. 입력란에 원문 또는 압축 문자열을 넣으면 화살표 아래에 결과가 나옵니다.
  4. 「복사」로 결과를 가져갑니다.

결과 해석

압축할 때는 입력란 아래에 「원본 ○바이트 → 압축 ○바이트 (○% 절감)」이 표시됩니다. 처음 들어 있는 예제 JSON은 URL용 방식에서 「원본 88바이트 → 압축 129바이트 (-47% 절감)」으로 나와 오히려 길어지고, UTF16 방식에서는 53글자 × 2바이트 = 106바이트(-20%)입니다. 사전에 쌓일 반복이 적은 짧은 글은 늘어나기 쉽고, 같은 키 이름이 수십 번 반복되는 긴 JSON일수록 효과가 큽니다. 해제했는데 「해제 실패」 문구가 나오면 방식이 압축할 때와 다르거나 복사 과정에서 문자열 끝이 잘린 경우가 대부분입니다.

주의할 점

  • 두 수치 모두 바이트 수입니다. 원본은 UTF-8 기준(한글 한 글자 = 3바이트)이고, 압축 결과는 URL용·Base64가 ASCII라 글자 수 그대로, UTF16은 결과 한 글자가 2바이트라 글자 수의 두 배로 셉니다. 브라우저 저장소(localStorage)는 원본도 UTF-16으로 저장하므로 실제 절감 폭은 이 표시와 조금 다를 수 있습니다.
  • UTF16 결과에는 화면에서 깨져 보이는 문자가 섞여 있어 URL이나 메일 본문에 쓰면 안 됩니다. Base64 결과도 + / =가 들어 있어 URL에 넣으려면 추가 인코딩이 필요합니다.
  • 압축은 암호화가 아닙니다. 누구나 같은 라이브러리로 풀 수 있으니 토큰이나 개인정보를 링크에 담지 마세요.

자주 묻는 질문

서버 쪽에서도 풀 수 있나요?
다른 언어용 LZ-String 포팅 구현을 쓰면 됩니다. 이때 압축에 쓴 방식과 짝이 맞는 해제 함수(예: URL용이면 decompressFromEncodedURIComponent)를 골라야 합니다.
입력한 내용이 저장되나요?
아닙니다. 압축과 해제는 브라우저에서만 이루어지며 어디에도 보관하지 않습니다.
