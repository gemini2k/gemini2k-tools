JSON 비교 (diff)

두 JSON을 구조적으로 비교해 어떤 경로가 추가·삭제·변경됐는지 보여 줍니다.

경로(dot notation)로 차이를 나열합니다. ＋추가 / －삭제 / ≠변경. 배열은 인덱스 기준 비교입니다. 모든 처리는 브라우저에서만 이루어집니다.

JSON 비교(diff) 사용 안내

무엇을 하는 도구인가

두 JSON을 텍스트가 아니라 구조로 비교합니다. 양쪽 객체의 키를 모두 모아 재귀적으로 내려가면서, B에만 있는 경로는 추가(＋), A에만 있는 경로는 삭제(－), 양쪽에 있지만 값이 다른 경로는 변경(≠)으로 나열하고 위에 각각의 개수를 요약합니다. 경로는 profile.age, tags.1처럼 점으로 이어 적으며, 배열 원소는 인덱스 번호로 표시됩니다.

언제 쓰나

  • API 버전을 올린 뒤 같은 요청의 응답 필드가 무엇이 바뀌었는지 확인할 때
  • 개발·운영 환경의 JSON 설정 파일에서 값이 다른 항목만 골라 볼 때
  • 키 순서나 들여쓰기가 달라 줄 단위 diff로는 차이가 너무 많이 나오는 두 JSON을 비교할 때

사용 방법

  1. 왼쪽 'JSON A (이전)'와 오른쪽 'JSON B (이후)'에 JSON을 넣습니다.
  2. 입력하는 즉시 비교 결과가 나옵니다. 둘 중 하나라도 문법이 틀리면 어느 쪽이 잘못됐는지 오류가 표시됩니다.

결과 해석

기본 예시를 비교하면 ≠ age : 30 → 31, ≠ tags.1 : "y" → "z", － vip = false, ＋ city = "서울" 네 줄이 나오고 요약은 추가 1, 삭제 1, 변경 2입니다. 키 순서가 달라도 같은 값이면 차이로 잡지 않습니다. 반면 숫자 1과 문자열 "1"은 다른 값으로 표시됩니다.

주의할 점

배열은 같은 인덱스끼리만 비교합니다. 그래서 배열 맨 앞에 원소 하나를 끼워 넣으면 뒤의 모든 원소가 한 칸씩 밀려 전부 변경으로 나오고 마지막 인덱스가 추가로 잡힙니다. 원소의 순서가 의미 없는 배열이라면 미리 정렬해서 넣으세요. 결과는 사람이 읽기 위한 목록이며, RFC 6902 JSON Patch처럼 다른 프로그램에 그대로 적용할 수 있는 형식은 아닙니다.

자주 묻는 질문

차이가 없으면 어떻게 나오나요?
요약이 모두 0이 되고 차이가 없다는 문구가 표시됩니다.
값이 객체에서 null로 바뀌면요?
더 내려가지 않고 그 경로 전체가 변경 한 줄로 표시됩니다.
