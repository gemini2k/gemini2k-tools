퍼지 검색 테스터

오타나 부분만 입력해도 비슷한 항목을 찾아 줍니다. 검색 기능 설계 전에 실험해 보세요.

정밀도(threshold) 0.4
오픈소스 Fuse.js(Apache-2.0, krisk/Fuse)를 자체 호스팅합니다. threshold가 높을수록 더 느슨하게 일치시킵니다. 모든 처리는 브라우저에서만 이루어집니다.

퍼지 검색 테스터 사용 안내

무엇을 하는 도구인가

한 줄에 하나씩 넣은 목록을 Fuse.js 7로 색인해, 검색어와 대략 비슷한 항목을 점수와 함께 보여 줍니다. Fuse.js의 근사 문자열 매칭(Bitap 알고리즘 기반)은 오타, 글자 빠짐, 부분 입력을 어느 정도 허용합니다. 이 도구에서 바꿀 수 있는 옵션은 threshold 하나이고 나머지는 Fuse.js 기본값입니다.

언제 쓰나

  • 자동완성이나 메뉴 검색에 Fuse.js를 넣기 전에 우리 데이터에서 threshold를 얼마로 둘지 정할 때
  • 상품명·지역명처럼 사용자가 오타를 자주 내는 목록이 어느 정도까지 찾아지는지 확인할 때
  • "검색이 안 된다"는 문의가 왔을 때 해당 검색어와 목록으로 재현해 볼 때

사용 방법

  1. '검색 대상 목록'에 항목을 한 줄에 하나씩 넣습니다. 앞뒤 공백과 빈 줄은 무시됩니다.
  2. '검색어'를 입력합니다. 비워 두면 전체 목록이 점수 0으로 나옵니다.
  3. '정밀도(threshold)' 슬라이더를 0~1 사이에서 움직이며 결과가 어떻게 바뀌는지 봅니다.

결과 해석

점수는 0이 완전 일치, 1에 가까울수록 다른 것이며 점수가 낮은 순으로 정렬됩니다. 기본 목록에서 수원을 찾으면 "경기도 수원시"가 0.103 정도로 나옵니다. 처음 화면의 검색어 부산광역은 "부산광역시"(0.001)와 한 글자만 다른 "울산광역시"(0.250)를 함께 보여 줍니다. 오타 예시로 과주를 넣으면 threshold 0.4에서는 결과가 없고, 0.6으로 올리면 "광주광역시"와 "제주특별자치도"가 둘 다 0.500으로 나옵니다. 오타를 받아 주려고 threshold를 올리면 엉뚱한 항목도 같이 걸린다는 점을 이렇게 확인할 수 있습니다.

주의할 점

Fuse.js 기본값은 문자열 앞부분에서 멀리 떨어진 일치일수록 점수를 깎습니다(location 0, distance 100). 긴 문장 끝쪽의 단어는 잘 안 찾아질 수 있으니 실제 서비스에서는 ignoreLocation 등의 옵션도 함께 검토하세요. 한글은 음절 단위로 비교하므로 초성 검색이나 자모 단위 오타(예: '광'과 '과')는 별도 처리 없이는 잘 잡히지 않습니다.

자주 묻는 질문

threshold 0이면 어떻게 되나요?
오타를 허용하지 않을 뿐 아니라 위치 감점도 받아들이지 않아, 사실상 검색어가 항목 맨 앞에서 일치할 때만 남습니다. 기본 목록에서 서울은 찾지만 수원은 "경기도 수원시"에 들어 있어도 결과가 없습니다.
목록이 수만 개여도 되나요?
입력할 때마다 색인을 새로 만들기 때문에 목록이 크면 입력 반응이 느려집니다. 이 도구는 옵션 감을 잡는 용도로 쓰세요.
