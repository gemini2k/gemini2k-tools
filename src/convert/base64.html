Base64 인코더·디코더

텍스트를 Base64로 인코딩하거나, Base64를 원래 텍스트로 디코딩합니다. (한글 UTF-8 지원)

모든 처리는 브라우저에서만 이루어집니다.

Base64 인코더·디코더 사용 안내

무엇을 하는 도구인가

Base64는 임의의 바이트를 A~Z, a~z, 0~9, +, / 64개 문자(그리고 끝맺음용 =)로 바꾸는 표기 방식입니다. 이메일 첨부, JSON 안의 바이너리, HTTP Basic 인증 헤더처럼 문자만 다룰 수 있는 곳에 데이터를 실어 보낼 때 씁니다. 이 도구는 입력한 텍스트를 먼저 UTF-8 바이트로 바꾼 뒤 Base64로 인코딩하고, 디코딩할 때는 그 반대로 처리하므로 한글도 깨지지 않습니다. 암호화가 아니라 단순한 표기 변환이라는 점은 꼭 기억하세요.

언제 쓰나

  • API 문서의 Base64 예시 값을 풀어 실제 내용을 확인할 때
  • Basic 인증 헤더용 '아이디:비밀번호' 문자열을 만들 때(테스트 환경에서)
  • 설정 파일이나 쿠버네티스 시크릿에 들어간 Base64 값을 읽어 볼 때
  • 한글이 포함된 텍스트를 시스템 간에 안전하게 전달해야 할 때

사용 방법

  1. '입력' 칸에 텍스트 또는 Base64 문자열을 붙여 넣습니다.
  2. 텍스트를 바꾸려면 '인코딩 →', Base64를 풀려면 '← 디코딩'을 누릅니다.
  3. '결과' 칸의 값을 '📋 결과 복사'로 복사합니다. '지우기'는 두 칸을 모두 비웁니다.

결과 해석

Hello를 인코딩하면 SGVsbG8=가 나옵니다. 5바이트를 3바이트 단위로 묶고 남은 자리를 =로 채운 것이라 결과 길이는 원본의 약 4/3배가 됩니다. 한글 '안녕'은 UTF-8로 6바이트이므로 7JWI64WV처럼 8글자가 됩니다. 반대로 7JWI64WV를 디코딩하면 다시 '안녕'이 나옵니다. 다른 도구에서 같은 한글을 인코딩했는데 결과가 다르다면, 그쪽이 UTF-8이 아닌 EUC-KR 등 다른 문자 인코딩을 썼을 가능성이 큽니다.

주의할 점

Base64는 누구나 바로 되돌릴 수 있으므로 비밀번호나 개인정보를 숨기는 용도로 쓰면 안 됩니다. 디코딩 결과가 UTF-8 텍스트가 아닌 경우(이미지나 압축 파일을 Base64로 만든 값 등)에는 텍스트로 풀 수 없어 오류 안내가 나옵니다. URL에 쓰는 변형(+ 대신 -, / 대신 _)은 그대로는 디코딩되지 않으니 -는 +로, _는 /로 바꿔 넣으세요. 이 도구는 파일 업로드를 지원하지 않고 텍스트만 다룹니다.

자주 묻는 질문

끝의 = 기호를 지워도 되나요?
=는 길이를 맞추는 채움 문자입니다. 이 도구의 디코더는 = 가 빠진 값도 대부분 풀어 내지만, 다른 시스템에 넘길 때는 원래대로 두는 것이 안전합니다.
입력한 내용이 서버로 전송되나요?
아니요. 인코딩과 디코딩은 브라우저 안에서만 처리되며 입력값을 외부로 보내지 않습니다.
