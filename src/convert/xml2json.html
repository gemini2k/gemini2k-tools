XML ↔ JSON 변환기

XML과 JSON을 서로 변환합니다.

↓
XML 속성은 @attr, 텍스트는 #text로 표현합니다. 같은 태그가 반복되면 배열로 변환합니다. 브라우저 내장 파서(DOMParser)를 사용하며 모든 처리는 브라우저에서만 이루어집니다.

XML ↔ JSON 변환기 사용 안내

무엇을 하는 도구인가

브라우저 내장 DOMParser로 XML을 읽어 JSON으로 바꾸고, 반대로 JSON 객체를 XML로 만들어 들여쓰기해 보여 줍니다. 변환 규칙은 단순합니다. 속성은 @속성명, 자식 요소와 함께 있는 텍스트는 #text 키가 되고, 같은 이름의 요소가 여러 번 나오면 배열로 묶습니다. 텍스트만 있는 요소는 문자열 값이 됩니다.

언제 쓰나

  • 공공데이터포털 등 XML로 응답하는 오픈 API 결과를 JSON으로 바꿔 구조를 살펴볼 때
  • SOAP·RSS 응답에서 필요한 필드 경로를 찾아 파싱 코드를 짤 때
  • 설정 파일이나 레거시 연동 메시지를 XML로 만들어 테스트할 때
  • XML 문서가 제대로 닫혀 있는지(구문 오류) 간단히 확인할 때

사용 방법

  1. 위쪽에서 「XML → JSON」 또는 「JSON → XML」을 고릅니다. 버튼을 누르면 입력칸이 해당 방향의 예시로 바뀝니다.
  2. 입력칸에 내용을 붙여 넣으면 아래에 결과가 바로 나옵니다. 구문 오류가 있으면 결과 대신 경고 문구가 나옵니다.
  3. 「복사」로 결과를 가져갑니다.

결과 해석

기본 예시는 book 요소가 두 번 나오므로 {"catalog":{"book":[{"@id":"1","title":"자바스크립트","price":"28000"}, …]}}처럼 배열이 됩니다. 이때 price의 28000은 숫자가 아니라 문자열입니다. XML에는 자료형 정보가 없어 모든 값이 문자열로 나오므로, 숫자 계산이 필요하면 받는 쪽에서 변환해야 합니다.

주의할 점

  • 요소가 한 번만 나오면 객체, 두 번 이상이면 배열이 됩니다. 같은 API라도 응답 건수에 따라 구조가 달라지니 파싱 코드에서 두 경우를 모두 처리하세요.
  • CDATA 구간은 일반 텍스트로 합쳐서 넣고, 주석은 버립니다. 네임스페이스 접두사는 soap:Body처럼 키 이름에 그대로 남습니다.
  • JSON → XML 변환은 값 안의 &, <, >, 따옴표를 엔티티로 이스케이프합니다. null 값은 빈 요소(<tag/>)가 되고, 최상위가 배열이면 <root> 아래 <item>을 반복하는 구조로 감쌉니다. 키 이름이 XML 태그로 쓸 수 없는 형태(공백 포함, 숫자로 시작 등)면 결과가 올바른 XML이 아니니 키를 먼저 정리하세요.
  • 변환 방향을 바꿀 때 입력칸이 비어 있거나 예제 그대로일 때만 예제가 채워집니다. 직접 붙여 넣은 내용은 그대로 둡니다.

자주 묻는 질문

XML 선언(<?xml version="1.0"?>)도 만들어 주나요?
JSON → XML 결과에는 선언이 붙지 않습니다. 필요하면 맨 앞에 직접 추가하세요.
변환했다가 되돌리면 원래 XML과 같아지나요?
대체로 비슷하지만 공백·주석·CDATA·요소 순서(텍스트와 자식 요소가 섞인 경우)는 보존되지 않습니다. CDATA는 내용만 남고 CDATA 표시는 사라집니다.
