HTML 살균기 (XSS 제거)

신뢰할 수 없는 HTML에서 <script>·onclick 같은 위험 요소를 제거해 안전한 HTML로 만듭니다.

미리보기 (정화 후)

오픈소스 DOMPurify(Apache-2.0/MPL-2.0, cure53/DOMPurify)를 자체 호스팅합니다. 모든 처리는 브라우저에서만 이루어집니다.

HTML 살균기 사용 안내

무엇을 하는 도구인가

외부에서 받은 HTML 조각에서 스크립트를 실행할 수 있는 요소를 걷어 내고, 화면에 넣어도 되는 HTML만 남기는 도구입니다. 보안 연구 그룹 cure53이 관리하는 오픈소스 DOMPurify의 기본 설정으로 동작하며, <script> 태그, onerror·onclick 같은 이벤트 속성, javascript: 링크처럼 XSS(크로스 사이트 스크립팅)에 쓰이는 요소를 제거합니다. 추가로 링크(<a>)와 이미지(<img>) 태그를 통째로 막을지 고를 수 있습니다.

언제 쓰나

  • 게시판·민원 접수 화면에 붙여 넣어진 HTML이 어떤 식으로 정리되는지 확인할 때
  • 웹 취약점 점검 결과로 받은 XSS 공격 문자열이 살균 후 어떻게 남는지 직접 보여 줄 때
  • 외부 메일이나 에디터에서 복사한 본문을 사내 페이지에 옮기기 전에 위험한 부분을 걷어 낼 때
  • 개발 중 DOMPurify 도입 효과를 설정별로 비교해 볼 때

사용 방법

  1. 위쪽 입력 칸에 검사할 HTML을 붙여 넣습니다. 기본으로 공격 예시가 들어 있습니다.
  2. 「링크(<a href>) 허용」, 「이미지 허용」 체크를 필요에 맞게 바꿉니다. 링크는 기본으로 꺼져 있습니다.
  3. 입력이나 옵션을 바꾸면 바로 다시 정화되며, 「정화하기」를 눌러도 됩니다.
  4. 결과 HTML을 「복사」로 가져가고, 아래 미리보기에서 실제 렌더링 모습을 확인합니다.

결과 해석

기본 예시를 넣으면 <p>와 <b>는 그대로 남고, 이미지 태그는 남되 onerror 속성이 빠지며, <script>는 내용까지 사라집니다. 링크를 허용하면 <a> 태그는 남지만 javascript: 주소는 지워집니다. 링크를 막은 상태에서는 <a> 태그만 사라지고 안쪽 글자(「클릭」)는 남습니다.

주의할 점

  • 이 도구는 결과를 확인하는 용도입니다. 실제 서비스에서는 사용자가 브라우저 쪽 검사를 우회해 바로 서버로 요청을 보낼 수 있으므로, 저장 또는 출력 시점에 서버나 렌더링 코드에서 살균을 다시 해야 합니다.
  • 정화된 HTML은 HTML 본문 위치에 넣을 때를 전제로 합니다. 속성값, 자바스크립트 문자열, URL 안에 넣으면 별도의 이스케이프가 필요합니다. 정화 후에 문자열을 다시 가공해도 안전성이 깨질 수 있습니다.
  • 기본 설정은 서식 태그와 일반 속성을 꽤 넓게 허용합니다. 표시 형식까지 엄격히 통제하려면 허용 태그 목록을 직접 정해 쓰는 설정이 필요합니다.
  • XSS를 막을 뿐 개인정보나 내부 링크가 들어 있는지는 판단하지 않습니다.

자주 묻는 질문

정규식으로 <script>만 지우면 안 되나요?
이벤트 속성, SVG, 인코딩을 섞은 우회 표기 등 실행 경로가 많아 정규식으로는 빠짐없이 막기 어렵습니다. 브라우저의 실제 HTML 해석기를 쓰는 DOMPurify 같은 검증된 라이브러리를 쓰는 이유입니다.
입력한 HTML이 전송되나요?
아닙니다. 정화와 미리보기는 브라우저 안에서만 이루어집니다.
