JWT 서명·검증기

JWT 토큰을 비밀키로 직접 발급(서명)하거나, 받은 토큰의 서명이 유효한지 확인합니다.

오픈소스 jsrsasign(MIT, kjur/jsrsasign)을 자체 호스팅합니다. 토큰과 비밀키는 서버로 전송되지 않고 브라우저에서만 처리됩니다.

JWT 서명·검증기 사용 안내

무엇을 하는 도구인가

JSON 페이로드와 비밀키로 HMAC 방식(HS256, HS384, HS512)의 JWT를 발급하고, 받은 토큰이 같은 비밀키로 서명된 것인지 확인하는 도구입니다. JWT는 RFC 7519에 정의된 형식으로, 헤더.페이로드.서명 세 부분을 Base64URL로 인코딩해 점으로 이은 문자열입니다. 서명과 검증에는 오픈소스 jsrsasign 라이브러리를 씁니다.

언제 쓰나

  • API 개발 중 권한(role)이나 사용자 ID를 바꿔 가며 테스트용 토큰을 빠르게 만들 때
  • 연계 기관이 보낸 토큰이 약속한 공유 비밀키로 서명된 것인지 확인할 때
  • 보안 점검에서 secret, my-secret-key 같은 기본 비밀키로 운영 토큰이 서명되어 있지 않은지 시험할 때

사용 방법

  1. 「서명(발급)」 탭에서 「페이로드 (JSON)」를 고칩니다. JSON 문법이 틀리면 오류 메시지가 나옵니다.
  2. 「알고리즘 / 비밀키」에서 HS256·HS384·HS512 중 하나를 고르고 비밀키를 넣은 뒤 「서명하기」를 누릅니다.
  3. 검증하려면 「검증」 탭으로 바꿔 토큰과 비밀키를 넣고 「검증하기」를 누릅니다.

결과 해석

생성된 토큰은 eyJ로 시작하는 경우가 많은데, 헤더 JSON {"를 Base64URL로 바꾼 모양이기 때문입니다. 검증 결과가 유효면 토큰 내용이 바뀌지 않았고 입력한 비밀키로 서명됐다는 뜻이며, 아래에 페이로드가 정리되어 보입니다. 유효하지 않음이 나오면 비밀키가 다르거나, 토큰이 중간에 수정·절단됐거나, HS 계열이 아닌 알고리즘(RS256 등)으로 서명된 토큰입니다.

주의할 점

  • JWT 페이로드는 암호화가 아니라 인코딩입니다. 서명과 상관없이 누구나 내용을 읽을 수 있으니 주민번호·연락처 같은 개인정보를 넣지 마세요.
  • 이 도구의 검증은 서명 일치 확인에 초점을 둡니다. 만료(exp) 판단에 매우 긴 유예 기간을 두고 있어 만료된 토큰도 유효로 나올 수 있습니다. 만료·발급자·대상 확인은 실제 서버 코드에서 따로 해야 합니다.
  • RS256·ES256 같은 공개키 방식 토큰은 지원하지 않습니다.
  • 운영 서버의 실제 서명 키는 웹 페이지에 입력하지 않는 것이 원칙입니다. 테스트 키로 동작을 확인하는 용도로 쓰세요.
