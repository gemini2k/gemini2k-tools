기능점수(FP) 간이 산정

데이터·트랜잭션 기능 개수로 미보정 기능점수(UFP)를 추정합니다.

간이법(평균복잡도) 가중치: 내부논리파일 7.5 · 외부연계파일 5.4 · 외부입력 4.0 · 외부출력 5.2 · 외부조회 3.9. 실제 대가산정은 보정계수가 필요합니다.

기능점수(FP) 간이 산정 사용 안내

무엇을 하는 도구인가

기능점수(Function Point)는 소프트웨어 규모를 코드 줄 수가 아니라 사용자에게 제공하는 기능의 양으로 재는 방법입니다. IFPUG 방식은 기능을 데이터 기능 2종(내부논리파일 ILF, 외부연계파일 EIF)과 트랜잭션 기능 3종(외부입력 EI, 외부출력 EO, 외부조회 EQ)으로 나눕니다. 이 도구는 다섯 유형의 개수를 받아 유형별 평균 복잡도 가중치를 곱해 미보정 기능점수(UFP)를 계산합니다. 가중치는 ILF 7.5, EIF 5.4, EI 4.0, EO 5.2, EQ 3.9로, 국내 SW사업 대가산정에서 쓰는 간이법의 평균 가중치와 같은 값입니다.

언제 쓰나

  • 사업 기획·예산 요구 단계에서 요구사항 목록만으로 개발 규모를 대략 잡아야 할 때
  • 제안서나 사업자가 제시한 규모가 기능 목록에 비해 지나치게 크거나 작은지 감을 잡을 때
  • 과업 변경 협의에서 추가된 화면·연계가 규모를 얼마나 늘리는지 비교할 때
  • 상세법 산정에 들어가기 전에 어느 유형이 규모를 좌우하는지 미리 볼 때

사용 방법

  1. 요구사항이나 화면·테이블 목록을 보며 기능을 다섯 유형으로 분류해 셉니다. ILF는 이 시스템이 직접 관리하는 논리적 데이터 묶음(회원, 신청서 등), EIF는 다른 시스템이 관리하고 이 시스템은 참조만 하는 데이터입니다.
  2. EI는 데이터를 등록·수정·삭제하는 처리, EO는 계산이나 가공이 들어간 출력(통계, 보고서), EQ는 가공 없이 조회만 하는 처리로 셉니다.
  3. 각 입력칸에 개수를 넣으면 유형별 점수와 합계 UFP가 바로 표시됩니다.

결과 해석

기본값으로 계산하면 ILF 8개 × 7.5 = 60.0, EIF 3개 × 5.4 = 16.2, EI 20개 × 4.0 = 80.0, EO 12개 × 5.2 = 62.4, EQ 15개 × 3.9 = 58.5로 합계 UFP 277.1 FP입니다. 이 값은 보정 전 규모이므로 개발 원가로 바로 바꾸면 안 됩니다. 실제 대가 산정에서는 여기에 규모·연계 복잡성·성능 요구 등 보정계수와 기능점수당 단가를 별도로 적용합니다. 유형별 점수 표를 보면 어디서 규모가 나오는지 알 수 있는데, EI가 지나치게 많다면 등록·수정·삭제를 화면 단위로 중복 계산하지 않았는지 다시 볼 만합니다.

주의할 점

이 도구는 모든 기능을 평균 복잡도로 본다는 가정의 간이 계산입니다. 데이터 요소(DET)·레코드 유형(RET)·참조 파일(FTR)을 따져 복잡도를 개별로 매기는 상세 산정과는 결과가 다를 수 있습니다. 계산 정확도보다 분류 기준이 결과를 더 크게 좌우하므로, 같은 사업은 같은 사람이나 같은 기준으로 세야 비교가 됩니다. 결과는 규모 추정의 참고값이며 계약 금액의 근거로 쓰려면 공인된 절차에 따른 산정이 필요합니다.

자주 묻는 질문

화면 하나가 기능 하나인가요?
아닙니다. 한 화면에서 등록·수정·삭제·조회를 모두 한다면 EI 3개와 EQ 1개처럼 처리 단위로 셉니다. 반대로 같은 처리를 하는 화면이 여러 개면 한 번만 셉니다.
배치 프로그램이나 연계 송신은 어떻게 세나요?
다른 시스템으로 가공한 데이터를 내보내면 EO, 외부에서 받은 데이터로 내부 파일을 갱신하면 EI로 보는 것이 일반적입니다. 연계 상대가 관리하는 데이터를 읽기만 하면 그 데이터는 EIF가 됩니다.
