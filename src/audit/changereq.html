변경요청(CR) 관리대장

변경요청의 접수부터 반영까지 통제·기록합니다.

승인 전 영향분석(일정·비용·범위)을 반드시 기록하세요. 데이터는 브라우저에만 저장됩니다.

변경요청(CR) 관리대장 사용 안내

무엇을 하는 도구인가

프로젝트 진행 중 들어오는 변경요청을 한 장의 표로 관리하는 대장입니다. 열은 CR번호, 요청일, 요청자, 변경내용, 영향분석, 우선순위(긴급·높음·보통·낮음), 상태(접수·검토·승인·반려·완료), 반영일로 구성되어 있습니다. 표 아래에는 전체 건수, 승인/완료 건수, 처리대기(접수+검토) 건수가 자동으로 집계됩니다. 별도 시스템 없이 브라우저만으로 쓸 수 있어 소규모 사업이나 유지보수 계약에서 변경 이력을 남기는 용도로 알맞습니다.

언제 쓰나

  • 구축 사업 중 현업 부서가 화면 항목이나 조회조건 추가를 요청할 때 접수 사실과 처리 결과를 남길 때
  • 요구사항 변경이 일정, 비용, 범위에 미치는 영향을 승인 전에 정리하고 발주처 확인을 받을 때
  • 정보시스템 감리에서 변경 통제 절차가 지켜졌는지 보기 위해 변경 건별 승인 여부와 반영일을 확인할 때
  • 유지보수 월간 보고서에 이번 달 처리한 변경 건수와 대기 건수를 적어야 할 때

사용 방법

  1. 처음 열면 예시 행(CR-001, 조회조건 추가)이 들어 있습니다. 필요 없으면 행 끝의 ✕로 지웁니다.
  2. [+ 행 추가]를 눌러 새 요청을 넣고 CR번호, 요청일, 요청자, 변경내용을 적습니다.
  3. 영향분석 칸에 수정 대상 화면·프로그램 수, 일정 지연 여부, 추가 비용 여부를 적습니다.
  4. 우선순위와 상태를 목록에서 고르고, 반영이 끝나면 상태를 완료로 바꾸고 반영일을 넣습니다.
  5. [CSV]로 내려받아 보고서나 회의 자료에 붙입니다. [비우기]는 모든 행을 지우므로 확인 창이 뜹니다.

결과 해석

집계 줄은 "3건 · 승인/완료 1 · 처리대기 2"처럼 나옵니다. 승인/완료는 상태가 승인 또는 완료인 건, 처리대기는 접수 또는 검토인 건이고, 반려는 어느 쪽에도 포함되지 않습니다. 예를 들어 5건 중 승인 1, 완료 2, 검토 1, 반려 1이면 "5건 · 승인/완료 3 · 처리대기 1"이 됩니다. 처리대기가 계속 쌓이면 변경 검토 회의가 제때 열리지 않는다는 신호로 볼 수 있고, 승인 상태로 오래 남은 건은 반영 일정이 밀리고 있다는 뜻입니다.

주의할 점

새로 추가한 행은 목록 상자에 첫 항목이 보이더라도 실제로 고르기 전까지는 값이 비어 있어 집계에서 빠집니다. 상태와 우선순위는 반드시 한 번 선택해 주세요. 데이터는 이 브라우저의 localStorage에만 저장되어 다른 사람과 공유되지 않고, 브라우저 데이터를 지우면 사라집니다. 여러 사람이 함께 써야 하거나 승인 서명 같은 증적이 필요하면 CSV를 정식 문서로 옮겨 관리하세요. 승인 권한이나 결재 흐름을 강제하는 기능은 없습니다.

자주 묻는 질문

CR번호는 자동으로 매겨지나요?
아닙니다. CR-002처럼 직접 입력합니다. 기관이나 사업의 번호 체계를 그대로 쓸 수 있도록 자유 입력으로 두었습니다.
반려된 요청은 지워야 하나요?
지우지 않는 것이 좋습니다. 반려 사유를 영향분석이나 변경내용 칸에 남겨 두면 같은 요청이 다시 들어왔을 때 근거로 쓸 수 있습니다.
