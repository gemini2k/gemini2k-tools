시스템 용량 산정

필요 처리량(TPS)과 데이터 스토리지 용량을 추정합니다.

TPS = 동시사용자 × 사용자당 시간당 요청 ÷ 3600 × 피크계수. 스토리지는 인덱스·여유율을 포함한 근사치입니다. 참고용 추정입니다.

시스템 용량 산정 도구 사용 안내

무엇을 하는 도구인가

신규 시스템을 구축하거나 장비를 증설할 때 가장 먼저 필요한 두 숫자, 피크 시간의 초당 처리 건수(TPS)와 보존 기간 동안 쌓일 데이터 용량을 간단한 식으로 추정합니다. 동시 사용자와 사용 패턴, 하루에 생기는 행 수와 행 크기만 알면 바로 계산되므로 사업 초기 규모 산정이나 제안서 검토 때 대략의 감을 잡는 데 씁니다.

언제 쓰나

  • 구축 사업의 하드웨어 규모를 정하기 전에 WAS와 DB가 감당해야 할 피크 TPS를 대략 잡을 때
  • 성능 테스트 목표 부하를 정하면서 시나리오의 목표 TPS가 실제 사용량과 맞는지 확인할 때
  • 감리에서 용량 산정서의 TPS나 스토리지 수치가 입력 가정과 맞게 계산됐는지 검산할 때
  • 로그나 이력 테이블의 보존 기간을 늘리면 스토리지가 얼마나 더 필요한지 비교할 때

사용 방법

  1. 첫 줄에 [동시 사용자], [사용자당 요청/시간], [피크계수]를 넣습니다. 피크계수는 평균 대비 가장 바쁜 시간대의 배수로, 출근 직후나 마감일처럼 쏠림이 있으면 2~3을 씁니다.
  2. 둘째 줄에 [일 발생 행 수], [행당 크기(byte)], [보존(년)]을 넣습니다. 행당 크기는 컬럼 길이의 합을 기준으로 잡습니다.
  3. 값을 바꾸면 위쪽 큰 숫자(TPS)와 표의 스토리지 단계별 값이 바로 갱신됩니다.

결과 해석

TPS = 동시 사용자 × 사용자당 시간당 요청 ÷ 3600 × 피크계수입니다. 기본값 500명, 시간당 120회, 피크계수 2를 넣으면 500 × 120 ÷ 3600 × 2 = 33.3 TPS이고, 괄호 안에는 올림한 34건/초가 함께 나옵니다. 스토리지는 세 단계로 보여 줍니다. 순수 데이터 = 일 행 수 × 행 크기 × 365 × 보존 연수, 여기에 인덱스 몫으로 1.5배, 다시 여유율 30%를 곱한 값이 권장 산정치입니다. 기본값(하루 10만 행, 500바이트, 3년)이면 순수 데이터 50.99GB, 인덱스 포함 76.49GB, 여유율 포함 99.43GB입니다. 용량 단위는 1024 기준으로 환산합니다.

주의할 점

인덱스 1.5배와 여유율 30%는 도구에 고정된 근사 계수입니다. 실제 인덱스 비율은 테이블 설계에 따라 크게 다르고, 백업본, 아카이브 로그, 첨부파일, 이중화 복제본, RAID 손실분은 이 계산에 들어 있지 않습니다. 데이터 증가율도 매년 같다고 가정합니다. TPS는 요청 한 건을 처리 한 건으로 보는 단순 모델이라 화면 하나가 여러 API를 호출하는 구조라면 요청 수를 그만큼 늘려 잡아야 합니다. 정식 산정에는 기관에서 쓰는 산정 기준과 실측 자료를 함께 쓰고, 이 결과는 비교·검산용으로 보세요.

자주 묻는 질문

동시 사용자와 전체 사용자는 어떻게 다른가요?
전체 가입자 중 같은 시간대에 실제로 접속해 요청을 보내는 사람의 수가 동시 사용자입니다. 전체 사용자 수를 그대로 넣으면 TPS가 크게 부풀려집니다.
여기서 나온 TPS로 서버 대수를 바로 정할 수 있나요?
서버 한 대가 처리할 수 있는 TPS는 업무 로직과 DB 부하에 따라 달라서 성능 테스트나 유사 시스템 실측이 있어야 정할 수 있습니다.
