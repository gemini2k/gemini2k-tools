JavaScript 코드 린트

코드의 잠재 오류·미사용 변수·위험 패턴을 정적 분석으로 찾습니다.

오픈소스 JSHint(MIT, jshint/jshint)를 자체 호스팅합니다. 모든 분석은 브라우저에서만 이루어집니다.

JavaScript 코드 린트 사용 안내

무엇을 하는 도구인가

붙여 넣은 JavaScript를 오픈소스 정적 분석기 JSHint로 검사해 문제 위치(줄:칸)와 메시지를 보여 줍니다. 코드를 실행하지 않고 읽기만 하므로 안전하게 돌려 볼 수 있습니다. 이 화면에는 다섯 가지 옵션이 고정으로 켜져 있습니다. ES2020 문법 허용(esversion 11), 브라우저 전역 객체 인정(browser), 선언하지 않은 변수 사용 경고(undef), 선언만 하고 쓰지 않은 변수 경고(unused), == 대신 === 사용 요구(eqeqeq)입니다. 입력을 고치면 0.3초 뒤 다시 검사합니다.

언제 쓰나

  • 빌드 도구나 린터가 갖춰지지 않은 오래된 공공 시스템의 화면 스크립트를 손볼 때
  • 소스코드 품질 점검이나 감리 표본 검토에서 의심 가는 함수 하나를 빠르게 확인할 때
  • 오타로 생긴 전역 변수, 쓰이지 않는 변수처럼 눈으로 놓치기 쉬운 문제를 찾을 때
  • 신입 개발자에게 느슨한 비교(==)나 세미콜론 누락이 왜 지적되는지 예를 들어 설명할 때

사용 방법

  1. 검사할 코드를 입력란에 붙여 넣습니다. 함수 하나만 넣어도 됩니다.
  2. 아래 표에서 L줄:칸 위치와 메시지를 확인합니다. 코드가 E로 시작하는 오류는 빨간색, 경고(W)와 정보성 메시지는 주황색입니다.
  3. 코드를 고치면 자동으로 다시 검사되므로 건수가 줄어드는 것을 보며 정리합니다.

결과 해석

기본 예시를 넣으면 5건이 나옵니다. 3번째 줄의 a == b에 "Expected '===' and instead saw '=='", 3·4번째 줄 끝에 "Missing semicolon" 2건, unused 변수와 어디서도 호출하지 않는 add 함수에 "is defined but never used" 2건입니다. 세미콜론 누락처럼 표기 문제도 있지만, 3번째 줄은 return 뒤에 값이 없어 a와 b가 같을 때 undefined를 돌려주는 코드라 실제 동작도 다시 볼 필요가 있습니다. 경고를 볼 때는 'is not defined'(오타·누락된 선언)를 가장 먼저, '=='와 미사용 변수를 그다음으로 정리하는 순서가 효율적입니다.

주의할 점

JSHint는 문법과 흔한 실수 패턴을 찾을 뿐, 로직 오류나 보안 취약점(XSS, 인젝션 등)을 판정하지 않습니다. 결과가 0건이라고 시큐어코딩 점검을 통과했다는 뜻이 아닙니다. 옵션을 바꿀 수 없어서 Node.js 코드는 require 같은 전역이 미선언으로 잡히고, 브라우저 코드라도 console과 alert는 개발용 전역으로 분류되어 'is not defined'로 표시됩니다. 한 파일 안에서만 보기 때문에 다른 스크립트 파일에서 선언한 전역 변수도 미선언으로 나옵니다.

자주 묻는 질문

다른 파일에 있는 전역 변수 경고를 없애고 싶습니다.
코드 맨 위에 /* global jQuery, myApp */ 같은 주석을 넣으면 JSHint가 해당 이름을 선언된 것으로 봅니다. 실제 프로젝트에서도 쓰는 방법이라 그대로 소스에 남겨 둬도 됩니다.
ESLint와 비교하면 어떤가요?
ESLint는 규칙을 세밀하게 조정하고 플러그인을 붙이기 좋아서 신규 프로젝트에 주로 쓰입니다. JSHint는 설정 없이 빠르게 기본 문제를 보는 데 알맞아서 레거시 코드 한두 파일을 확인할 때 부담이 적습니다.
