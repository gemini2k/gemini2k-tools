위험·이슈 관리대장

위험과 이슈를 식별·평가하고 대응 상태를 추적합니다.

영향도·발생가능성이 모두 '상'이면 최우선 대응 대상입니다. 데이터는 브라우저에만 저장됩니다.

위험·이슈 관리대장 사용 안내

무엇을 하는 도구인가

위험(Risk)은 아직 일어나지 않았지만 일어날 수 있는 일이고, 이슈(Issue)는 이미 벌어져 대응이 필요한 일입니다. 둘을 한 대장에서 관리하면 위험이 이슈로 바뀌는 시점을 놓치지 않습니다. 이 도구는 ID·구분·내용·영향도·발생가능성·대응방안·담당·상태를 행 단위로 기록하고, 아직 해결되지 않은 건수와 고위험 건수를 자동으로 셉니다.

언제 쓰나

  • 주간보고 때 미해결 위험·이슈 목록과 담당자를 정리해 공유할 때
  • 요구사항 변경이 잦거나 연계기관 일정이 불확실해 조기 경보가 필요할 때
  • 감리 점검에서 위험관리 활동이 실제로 기록·추적되고 있는지 증적을 만들 때
  • 운영 단계에서 노후 장비, 기술지원 종료 SW 같은 잠재 위험을 꾸준히 관리할 때

사용 방법

  1. "행 추가"로 줄을 만들고 ID(예: R-01, I-03)와 구분(위험/이슈)을 정합니다.
  2. "내용"에 원인과 결과가 드러나게 적습니다. "일정 지연"보다 "연계기관 API 제공 지연 시 통합시험 2주 순연"이 낫습니다.
  3. 영향도와 발생가능성을 상·중·하로 고르고, "대응방안"과 "담당"을 채웁니다.
  4. 진행에 따라 "상태"를 식별 → 대응중 → 해결 → 종료로 바꿉니다. 필요하면 "CSV"로 내려받아 보고서에 첨부합니다.

결과 해석

표 아래 요약은 "n건 미해결 · 고위험(영향·가능성 모두 상) m건 / 전체 k건" 형식입니다. 미해결은 상태가 "해결"이나 "종료"가 아닌 건(식별·대응중)의 수이고, 고위험은 영향도와 발생가능성이 둘 다 "상"인 건의 수입니다.

예를 들어 전체 8건 중 식별 2·대응중 3·해결 2·종료 1이면 미해결은 5건입니다. 이 중 영향·가능성 모두 상인 건이 2건이라면, 이 2건은 다음 주간회의 첫 안건으로 올리고 대응 기한을 정해야 합니다. 고위험 건수는 상태와 관계없이 세므로, 해결된 건이 섞여 있을 수 있다는 점도 함께 보세요.

주의할 점

  • 영향도·가능성은 3단계 정성 평가이며, 금액 환산이나 점수 행렬(5×5 등)은 하지 않습니다.
  • "상·중"이나 "중·상" 조합은 고위험으로 세지 않습니다. 이런 건도 대응 기한을 정해 두는 것이 좋습니다.
  • 변경 이력(언제 상태가 바뀌었는지)은 남지 않습니다. 이력이 필요하면 주기적으로 CSV를 날짜별로 저장하세요.
  • 데이터는 이 브라우저의 로컬 저장소에만 있습니다.

자주 묻는 질문

위험이 실제로 터지면 새 행을 만들어야 하나요?
기존 행의 구분을 "이슈"로 바꾸고 대응방안을 갱신해도 되고, 추적성을 위해 새 이슈 행을 만들고 내용 칸에 원래 위험 ID(예: R-01에서 전환)를 적어도 됩니다. 팀 안에서 한 방식으로 통일하세요.
"해결"과 "종료"는 무엇이 다른가요?
보통 해결은 조치를 마친 상태, 종료는 조치 효과를 확인하고 관리 대상에서 빼기로 합의한 상태로 구분해 씁니다.
