보안 HTTP 헤더 점검·생성

응답 헤더를 붙여넣어 보안 헤더 적용 여부를 점검합니다.

권장 헤더

주요 보안 응답 헤더의 존재 여부와 기본 값(HSTS max-age 180일 이상, nosniff, DENY/SAMEORIGIN 또는 frame-ancestors, CSP unsafe-inline/unsafe-eval)을 점검합니다. 권장값은 환경에 맞게 조정하세요. 모든 처리는 브라우저에서만 이루어집니다.

보안 HTTP 헤더 점검 도구 사용 안내

무엇을 하는 도구인가

웹 서버 응답에 브라우저 보호 기능을 켜는 보안 헤더가 붙어 있는지 확인하는 도구입니다. 응답 헤더 텍스트를 붙여넣으면 다음 6개 헤더가 있는지와 값이 기본 기준을 넘는지를 ✅(적정)·⚠️(보완 필요)·❌(미적용)로 표시하고, 바로 복사해 쓸 수 있는 권장 설정 예시를 함께 보여 줍니다.

  • Strict-Transport-Security(HSTS): 이후 접속을 HTTPS로 강제
  • Content-Security-Policy(CSP): 허용된 출처의 스크립트만 실행해 XSS 피해를 줄임
  • X-Frame-Options: 다른 사이트가 내 페이지를 iframe으로 감싸는 클릭재킹 방지
  • X-Content-Type-Options: 브라우저의 MIME 타입 추측(스니핑) 방지
  • Referrer-Policy: 다른 사이트로 넘어갈 때 보내는 주소 정보 제한
  • Permissions-Policy: 위치·카메라 등 브라우저 기능 사용 제한

언제 쓰나

  • 웹 취약점 점검 결과에 "보안 헤더 미설정"이 나와 조치 범위를 정리할 때
  • WAS·웹서버 설정을 바꾼 뒤 헤더가 실제 응답에 반영됐는지 확인할 때
  • 감리나 보안 점검에서 여러 서비스의 헤더 적용 현황을 비교표로 만들 때

사용 방법

  1. 응답 헤더를 구합니다. 명령줄에서 curl -I https://대상주소 를 실행하거나, 브라우저 개발자도구 네트워크 탭에서 문서 요청의 Response Headers를 복사합니다.
  2. 입력칸에 붙여넣으면 즉시 결과표가 갱신됩니다. 대소문자는 구분하지 않습니다.
  3. "권장 헤더" 상자의 예시 값을 참고해 서버 설정(nginx add_header, Apache Header set 등)에 반영합니다.

결과 해석

상단의 "n/6 적정"은 6개 헤더 중 응답에 들어 있고 값도 아래 기준을 통과한 개수이며, 괄호 안에 보완 필요(⚠️)와 미적용(❌) 개수가 따로 나옵니다. 기본 예시는 x-content-type-options: nosniff만 있어 1/6 적정이고 나머지 5개가 ❌입니다. 값 점검 기준은 다음과 같습니다.

  • HSTS: max-age가 15552000초(180일) 이상이어야 ✅, 없거나 그보다 짧으면 ⚠️입니다. includeSubDomains 포함 여부는 판정에 넣지 않고 참고로만 적어 줍니다.
  • CSP: 'unsafe-inline'이나 'unsafe-eval'이 들어 있으면 XSS 방어 효과가 크게 줄어 ⚠️로 표시합니다.
  • 클릭재킹 방지: X-Frame-Options가 DENY 또는 SAMEORIGIN이면 ✅, 다른 값(폐기된 ALLOW-FROM 등)이면 ⚠️입니다. X-Frame-Options가 없어도 CSP에 frame-ancestors가 있으면(값이 * 하나가 아닐 때) 보호된 것으로 보고 ✅로 표시합니다.
  • X-Content-Type-Options: 값이 정확히 nosniff가 아니면 ⚠️입니다.
  • Referrer-Policy: unsafe-url은 전체 주소를 외부로 보내므로 ⚠️, 그 밖의 값은 ✅입니다. Permissions-Policy는 있는지만 봅니다.

HTTPS로 운영하는 서비스라면 최소한 HSTS, X-Content-Type-Options, X-Frame-Options(또는 CSP frame-ancestors)부터 갖추는 것이 무난한 출발점입니다.

권장값 예: HSTS는 max-age=31536000; includeSubDomains(1년), X-Frame-Options는 DENY, Referrer-Policy는 strict-origin-when-cross-origin입니다.

주의할 점

  • 값 점검은 위에 적은 단순 기준뿐입니다. ✅여도 CSP의 script-src에 너무 넓은 출처(https: 전체, 와일드카드 도메인)가 들어 있거나 Permissions-Policy가 필요한 기능을 다 열어 두는 경우는 걸러내지 못하니 값은 직접 읽어 보세요.
  • 같은 헤더가 여러 줄이면 하나로 이어 붙여 판정합니다. 응답 하나의 헤더만 붙여넣어야 결과가 정확합니다(리다이렉트 응답까지 함께 붙이면 섞입니다).
  • 권장 CSP default-src 'self'는 출발점일 뿐입니다. 외부 CDN·분석 스크립트를 쓰는 사이트에 그대로 넣으면 화면이 깨질 수 있으니 시험 환경에서 먼저 확인하세요.
  • HSTS는 한번 적용되면 브라우저가 기간 동안 HTTP 접속을 거부하므로, 모든 하위 도메인이 HTTPS를 지원하는지 확인한 뒤 includeSubDomains를 넣으세요.

자주 묻는 질문

URL만 넣으면 자동으로 가져올 수는 없나요?
이 도구는 브라우저 안에서만 동작하고 대상 서버에 직접 요청하지 않습니다. 헤더는 curl이나 개발자도구로 직접 복사해 넣어야 합니다.
X-XSS-Protection은 왜 점검하지 않나요?
최신 브라우저 대부분이 해당 기능을 제거해 실효성이 낮고, 지금은 CSP로 대체하는 것이 일반적입니다. 그래서 이 도구의 점검 목록에도 들어 있지 않습니다.
