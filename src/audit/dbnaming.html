DB 명명규칙 검사기

테이블/컬럼명이 표준 명명규칙을 지키는지 점검합니다.

기본 규칙: 영문 소문자·숫자·언더스코어만, 숫자로 시작 금지, 예약어 금지, 길이 제한. 규칙은 기관 표준에 맞게 참고하세요. 모든 처리는 브라우저에서만 이루어집니다.

DB 명명규칙 검사기 사용 안내

무엇을 하는 도구인가

테이블명이나 컬럼명 목록을 한 줄에 하나씩 넣으면 기본 명명규칙을 지키는지 이름마다 판정합니다. 검사하는 규칙은 다섯 가지입니다. 영문 소문자·숫자·언더스코어만 쓸 것(대문자 허용을 켜면 대문자도 허용), 숫자로 시작하지 않을 것, 지정한 최대 길이를 넘지 않을 것, 자주 문제가 되는 SQL 예약어와 같지 않을 것, 한글을 포함하지 않을 것입니다. 이름이 수백 개인 설계서를 눈으로 훑다 보면 놓치기 쉬운 위반을 한 번에 걸러 줍니다.

언제 쓰나

  • 설계 단계에서 테이블 정의서의 물리명 목록을 DDL로 만들기 전에 규칙 위반을 미리 걸러낼 때
  • 감리에서 데이터베이스 설계 산출물의 명명 표준 준수 여부를 표본 점검할 때
  • 운영 DB의 information_schema에서 뽑은 컬럼명 목록을 넣어 표준에서 벗어난 이름을 찾을 때
  • DBMS를 바꾸는 이관 작업에서 대소문자나 길이 제한 때문에 문제가 될 이름을 미리 찾을 때

사용 방법

  1. 입력란에 이름을 한 줄에 하나씩 붙여넣습니다. 앞뒤 공백과 빈 줄은 무시됩니다.
  2. [최대 길이]에 기관 표준이나 대상 DBMS의 식별자 길이 제한을 넣습니다. 기본값은 30입니다.
  3. 대문자 이름을 표준으로 쓰는 조직이라면 [대문자 허용]을 체크합니다.
  4. 결과 표에서 ❌ 표시된 이름과 오른쪽 위반 사유를 확인합니다.

결과 해석

상단의 "통과 개수/전체 개수"는 모든 규칙을 지킨 이름의 수입니다. 위반 사유는 한 이름에 여러 개가 함께 붙을 수 있습니다. 기본 예시 7개를 그대로 두면 user_master, customer_name, ord_dt만 통과해 3/7이 나옵니다. USER_LOG는 대문자 때문에, 2nd_table은 숫자로 시작해서, order는 예약어라서, tbl_상품은 허용 문자 위반과 한글 포함 두 가지 사유로 걸립니다. 여기서 [대문자 허용]을 켜면 USER_LOG가 통과해 4/7이 됩니다.

주의할 점

예약어 목록은 select, from, where, order, group, table, user, date, desc, asc, index, key, int, char, number 15개뿐이라 DBMS별 전체 예약어를 대신하지 못합니다. 이름 전체가 예약어와 같을 때만 걸리므로 user_master처럼 예약어를 포함한 이름은 통과합니다. 표준 단어 사전에 등록된 단어인지, 접두어·접미어(TB_, _CD, _DT 등) 규칙을 따르는지, 약어가 일관된지는 검사하지 않습니다. 기관마다 명명 표준이 다르므로 결과는 기본 형식 점검으로만 보고, 세부 규칙은 해당 사업의 데이터 표준 정의서와 대조하세요.

자주 묻는 질문

최대 길이는 얼마로 두면 되나요?
대상 DBMS의 식별자 길이 제한과 기관 표준 중 더 짧은 값을 쓰면 됩니다. 버전마다 제한이 달라 실제 사용하는 DBMS 문서를 확인하세요.
테이블명과 컬럼명을 섞어 넣어도 되나요?
됩니다. 이 도구는 이름 문자열만 보므로 종류를 구분하지 않습니다. 다만 테이블과 컬럼의 길이 기준이 다르면 나눠서 검사하세요.
