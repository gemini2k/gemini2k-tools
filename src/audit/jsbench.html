JavaScript 코드 벤치마크

두 코드의 초당 처리횟수(ops/sec)를 통계적으로 비교합니다.

공통 준비(setup) — 선택
오픈소스 Benchmark.js(MIT, bestiejs/benchmark.js)와 lodash(MIT)를 자체 호스팅합니다. 측정에 수 초가 걸릴 수 있습니다. 모든 실행은 브라우저에서만 이루어집니다.

JavaScript 코드 벤치마크 사용 안내

무엇을 하는 도구인가

같은 일을 하는 두 코드 조각 A와 B를 브라우저에서 반복 실행해 초당 실행 횟수(ops/sec)를 비교합니다. 측정은 오픈소스 Benchmark.js가 맡는데, 한 번만 재고 끝내지 않고 충분한 시간 동안 여러 번 샘플을 모은 뒤 평균과 오차 범위를 계산합니다. "문자열 += 가 빠르냐, 배열 join이 빠르냐" 같은 논쟁을 감이 아니라 숫자로 정리할 때 씁니다.

언제 쓰나

  • 화면 렌더링이나 대량 데이터 가공 루프에서 구현 방식 두 가지 중 하나를 고를 때
  • 코드 리뷰에서 "이렇게 바꾸면 더 빠르다"는 주장을 직접 확인할 때
  • 정규식, 정렬 비교 함수, 객체 복사 방식처럼 자주 호출되는 작은 함수를 다듬을 때
  • 브라우저별 성능 차이를 확인하려고 같은 코드를 여러 브라우저에서 돌려 볼 때

사용 방법

  1. '코드 A'와 '코드 B'에 비교할 코드를 각각 넣습니다. 한쪽을 비워 두면 그 코드는 측정에서 빠집니다.
  2. 두 코드가 함께 쓸 데이터가 있으면 '공통 준비(setup)'를 펼쳐 var data=[...]처럼 준비 코드를 넣습니다. 준비 코드는 측정 시간에 포함되지 않습니다.
  3. [벤치마크 실행]을 누르고 상태가 '완료 ✓'로 바뀔 때까지 기다립니다. 수 초가 걸리며 그동안 탭을 바꾸지 않는 편이 좋습니다.

결과 해석

표는 빠른 순으로 정렬되고 가장 빠른 코드에 ★가 붙습니다. ops/sec는 1초에 몇 번 실행했는지, ±오차는 상대 오차 범위(rme), 샘플은 측정에 쓴 표본 수, 상대는 가장 빠른 코드 대비 비율입니다. 예를 들어 A가 120,000 ops/sec ±1.5%, B가 80,000 ops/sec ±2.0%라면 B의 상대 값은 0.67×이고 아래에 "A가 1.50× 더 빠릅니다"라고 나옵니다. 두 결과의 차이가 오차 범위를 합친 것보다 작다면 사실상 같은 성능으로 보는 것이 맞습니다.

주의할 점

결과는 지금 쓰는 브라우저, 기기, 그 순간의 부하에 따라 달라집니다. 같은 코드도 다시 돌리면 몇 % 차이가 나는 것이 정상입니다. 계산 결과를 아무 데도 쓰지 않는 코드는 엔진 최적화로 일부가 생략되어 비현실적으로 빠르게 나올 수 있습니다. 이 도구는 두 결과의 순위와 비율만 보여 줄 뿐 통계적으로 유의한 차이인지 검정하지는 않습니다. 마이크로벤치마크에서 몇 배 빨라도 실제 화면 응답시간에는 차이가 안 날 수 있으니, 병목이 확인된 코드에만 쓰세요. 입력한 코드는 이 페이지에서 그대로 실행되므로 출처를 모르는 코드를 붙여 넣지 마세요.

자주 묻는 질문

비동기 코드(Promise, fetch)도 잴 수 있나요?
이 화면은 동기 코드 측정용입니다. 비동기 함수를 넣으면 호출만 하고 완료를 기다리지 않으므로 실제 처리 시간이 아니라 호출 비용만 재게 됩니다.
오류가 나면 어떻게 표시되나요?
코드 실행 중 예외가 나면 빨간 오류 메시지가 표시되고 결과 표는 나오지 않습니다. setup에서 선언한 변수 이름을 A·B에서 똑같이 쓰고 있는지 먼저 확인하세요.
