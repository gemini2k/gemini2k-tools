요구사항 우선순위 결정

가치·비용·위험을 평가해 우선순위를 산정합니다.

우선순위 점수 = 가치 ÷ (비용×0.6 + 위험×0.4). MoSCoW로 범위(Scope)를 합의하세요. 데이터는 브라우저에만 저장됩니다.

요구사항 우선순위 결정 도구 사용 안내

무엇을 하는 도구인가

요구사항은 늘 예산과 일정보다 많습니다. 이 도구는 요구사항마다 가치·비용·위험을 1~5로 매기고 MoSCoW(Must·Should·Could·Won't) 분류를 붙여, 이번 차수에 무엇을 넣고 무엇을 미룰지 합의할 근거 표를 만듭니다. 하단 요약에는 MoSCoW 분류별 건수와 요구사항별 우선순위 점수 순위표가 함께 표시됩니다.

언제 쓰나

  • 요구사항 분석 단계에서 제안요청서 요구사항과 현업 추가 요청이 섞여 범위가 불어날 때
  • 예산이 삭감돼 1차 사업 범위를 줄여야 하고, 무엇을 2차로 넘길지 정해야 할 때
  • 과업심의나 변경관리 회의에 "왜 이 기능을 뺐는지" 설명 자료가 필요할 때
  • 감리에서 범위 확정 근거와 우선순위 결정 과정이 기록돼 있는지 확인할 때

사용 방법

  1. "행 추가"로 줄을 만들고 "요구사항" 칸에 이름을 적습니다.
  2. "가치(1-5)"는 업무 효과가 클수록 5, "비용(1-5)"과 "위험(1-5)"은 개발 부담·불확실성이 클수록 5를 고릅니다.
  3. MoSCoW 칸에서 Must(없으면 사업 실패), Should(중요하지만 대안 있음), Could(여유 있으면), Won't(이번엔 제외) 중 하나를 고릅니다.
  4. 입력은 자동 저장되며, "CSV"로 내려받아 회의 자료에 붙입니다.

결과 해석

요약줄의 "Must 3 · Should 4 · Could 2 · Won't 1" 같은 건수로 범위의 균형을 봅니다. Must가 전체의 절반을 훌쩍 넘으면 사실상 우선순위를 정하지 않은 것과 같습니다.

우선순위 점수는 가치 ÷ (비용×0.6 + 위험×0.4)로 계산되며, 요약 아래 순위표에 MoSCoW 등급 순(Must → Should → Could → Won't)으로 묶고 같은 등급 안에서는 점수가 높은 순으로 표시됩니다. 기본 예시로 계산하면 "핵심 결제 기능"(가치5·비용3·위험2)은 5 ÷ 2.6 ≈ 1.92, "테마 변경"(가치2·비용1·위험1)은 2 ÷ 1.0 = 2.00입니다. 점수만 보면 테마 변경이 앞서지만 결제는 Must라서 순위표 맨 위에 옵니다. 점수는 같은 MoSCoW 등급 안에서 순서를 정할 때 쓰고, 등급 자체는 업무 판단으로 정해야 한다는 뜻입니다. 점수는 화면 표시용이라 CSV에는 들어가지 않습니다.

주의할 점

  • 1~5 점수는 주관적입니다. 현업·개발·PM이 따로 매긴 뒤 차이가 큰 항목만 토론하면 회의 시간이 줄어듭니다.
  • 요구사항 간 선후 의존관계(예: 인증이 있어야 결제 가능)는 반영하지 않습니다.
  • 데이터는 이 브라우저에만 저장되므로 최종본은 CSV로 보관하세요.

자주 묻는 질문

법령상 의무 기능은 점수가 낮아도 Must인가요?
그렇습니다. 개인정보 처리, 접근성, 보안 요건처럼 지키지 않으면 사업이 성립하지 않는 항목은 점수와 무관하게 Must로 둡니다.
Won't는 지워도 되지 않나요?
지우지 말고 남겨 두세요. "이번 범위에서 제외했다"는 합의 기록이 있어야 나중에 누락 시비가 생기지 않습니다.
