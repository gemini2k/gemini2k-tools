페어와이즈(All-Pairs) 케이스 생성

모든 값 쌍을 덮는 최소 케이스를 만들어 조합 폭발을 줄입니다.

전체 조합 대비 케이스 수를 크게 줄이면서 2-요소 상호작용 결함을 검출합니다. 한 줄에 파라미터: 값1, 값2, ...로 입력하세요. 그리디 알고리즘 기반(최소에 근접). 모든 처리는 브라우저에서만 이루어집니다.

페어와이즈(All-Pairs) 케이스 생성 사용 안내

무엇을 하는 도구인가

여러 입력 조건(파라미터)과 그 값들을 넣으면, 서로 다른 두 파라미터의 값 쌍이 적어도 한 번씩은 등장하도록 테스트 조합을 골라 줍니다. 실제 결함의 상당수는 한 가지 값이나 두 값의 만남에서 생긴다는 경험칙에 기댄 기법으로, 전체 조합을 다 돌리지 않고도 2개 요소 사이의 상호작용은 빠짐없이 시험할 수 있습니다. 생성은 남은 값 쌍을 가장 많이 덮는 값을 하나씩 골라 나가는 그리디(탐욕) 방식이라, 이론상 최소 개수에 가깝지만 항상 최소를 보장하지는 않습니다.

언제 쓰나

  • 브라우저·OS·결제수단·언어처럼 환경 조합이 많은 웹 서비스의 호환성 시험 범위를 정할 때
  • 민원 신청 화면에서 신청 유형·신청인 구분·첨부 여부·수령 방법 같은 옵션 조합을 시험할 때
  • 설정 항목이 많은 시스템의 설정 조합 회귀 시험을 줄일 때
  • 사업자가 "전수 조합은 불가"라고 할 때 어느 정도로 줄일 수 있는지 근거를 제시할 때

사용 방법

  1. 한 줄에 파라미터: 값1, 값2, 값3 형식으로 적습니다. 콜론 앞이 파라미터 이름, 뒤가 쉼표로 구분한 값 목록입니다. 콜론이 없는 줄은 무시합니다.
  2. 파라미터를 2개 이상 넣고 [페어와이즈 생성]을 누릅니다.
  3. 요약에서 케이스 수와 전체 조합 대비 감소율을 확인하고, 표의 각 행을 테스트 케이스로 씁니다.
  4. [⬇️ CSV]로 내려받아 테스트케이스 명세서에 기대 결과 열을 붙입니다.

결과 해석

기본 예시는 브라우저 4 × OS 4 × 결제 3 × 언어 2 = 96개 전체 조합인데, 생성 결과는 16개 케이스로 약 83% 줄어듭니다. 값이 가장 많은 두 파라미터(브라우저 4, OS 4)의 쌍만 해도 16가지라서 이보다 더 줄일 수는 없습니다. 즉 케이스 수의 하한은 값 개수가 가장 많은 두 파라미터의 값 수를 곱한 것이고, 파라미터를 하나 더 추가해도 케이스가 크게 늘지 않는 것이 이 기법의 장점입니다.

주의할 점

보장하는 것은 2개 값의 조합까지입니다. 세 가지 조건이 동시에 맞아야 드러나는 결함은 놓칠 수 있으니, 업무상 중요한 조합(예: 가장 많이 쓰는 브라우저+OS+결제수단)은 따로 케이스로 추가하세요. "Windows + Safari", "Android + Safari"처럼 현실에서 불가능한 조합을 제외하는 제약 조건 기능이 없어서, 생성 결과에 불가능한 행이 나오면 수동으로 바꾸거나 빼야 합니다. 값 이름에 쉼표나 콜론이 들어가면 다르게 나뉘니 다른 기호로 바꿔 적으세요.

자주 묻는 질문

결정표와는 언제 구분해서 쓰나요?
파라미터들이 서로 독립적인 환경·옵션 값이면 페어와이즈가 효율적이고, 조건 조합에 따라 결과가 바뀌는 업무 규칙(할인, 자격 판정)을 검증할 때는 결정표처럼 모든 조합을 보는 편이 안전합니다.
생성할 때마다 결과가 달라지나요?
입력이 같으면 같은 결과가 나옵니다. 다만 파라미터 순서나 값 순서를 바꾸면 고르는 순서가 달라져 케이스 구성과 개수가 조금 달라질 수 있습니다.
