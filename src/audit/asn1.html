ASN.1 / DER 디코더

PEM 또는 16진수 DER의 ASN.1 구조를 계층으로 해석합니다.

오픈소스 jsrsasign(MIT, kjur/jsrsasign)을 자체 호스팅합니다. 모든 처리는 브라우저에서만 이루어집니다.

ASN.1 / DER 디코더 사용 안내

무엇을 하는 도구인가

인증서, 개인키, 인증서 서명 요청(CSR)처럼 공개키 기반구조에서 쓰는 파일은 대부분 ASN.1로 정의된 구조를 DER 규칙으로 직렬화한 바이너리입니다. PEM 파일은 이 DER을 Base64로 감싸고 앞뒤에 BEGIN/END 줄을 붙인 것일 뿐입니다. 이 도구는 PEM 텍스트나 16진수 DER을 받아 SEQUENCE, SET, INTEGER, OBJECT IDENTIFIER, BIT STRING, 문맥 태그([0], [3] 등) 같은 요소를 들여쓰기 계층으로 펼쳐 보여 줍니다. OID는 알려진 이름이 있으면 이름과 함께 표시됩니다. 해석에는 오픈소스 jsrsasign 라이브러리의 ASN1HEX 모듈을 씁니다.

언제 쓰나

  • 인증서 파서나 서명 검증 프로그램이 "잘못된 형식" 오류를 낼 때, 어느 위치의 어떤 태그에서 구조가 어긋났는지 직접 확인할 때
  • 보안 점검 중 받은 인증서에 어떤 확장 필드가 어떤 순서로 들어 있는지 원형 그대로 보고 싶을 때
  • HSM이나 외부 기관 장비가 내보낸 16진수 덤프가 정상적인 DER 구조인지 판별할 때
  • ASN.1 인코딩을 처음 공부하면서 X.509 인증서가 실제로 어떤 층으로 쌓여 있는지 눈으로 익힐 때

사용 방법

  1. 입력란에 -----BEGIN ...----- 으로 시작하는 PEM 전체를 붙여넣거나, DER 바이트를 16진수로 붙여넣습니다. 16진수 사이의 공백, 콜론, 줄바꿈은 자동으로 무시됩니다.
  2. 입력을 멈추면 잠시 뒤 아래 출력 영역에 구조가 펼쳐집니다.
  3. 샘플이 필요하면 [예시(인증서) 넣기]를 누릅니다. 브라우저에서 즉석으로 RSA 512비트 키를 만들고 CN=gemini2k.co.kr 주체의 시험용 인증서를 생성해 넣어 줍니다.

결과 해석

들여쓰기 한 단계가 한 겹의 포함 관계입니다. X.509 인증서라면 최상위 SEQUENCE 아래에 세 덩어리가 보입니다. 첫째가 서명 대상인 tbsCertificate SEQUENCE, 둘째가 서명 알고리즘 OID(예: sha256WithRSAEncryption), 셋째가 서명값 BIT STRING입니다. tbsCertificate 안의 [0]은 버전, 이어지는 INTEGER는 일련번호, 그다음에 발급자, 유효기간(UTCTime 두 개), 주체, 공개키 정보가 오고 확장 필드는 [3] 태그 아래에 묶입니다. 태그 순서가 이 틀과 다르면 생성 프로그램 쪽 문제를 의심할 수 있습니다.

주의할 점

BEGIN/END 줄이 없는 순수 Base64는 16진수로 오인되어 깨진 결과가 나오므로 PEM 머리줄을 붙이거나 16진수로 바꿔 넣어야 합니다. "0x" 같은 접두어도 숫자 0이 남아 바이트가 어긋날 수 있으니 지우고 넣으세요. 이 도구는 구조를 보여 줄 뿐 서명 검증, 유효기간 판정, 체인 검사는 하지 않습니다. 예시 인증서의 512비트 RSA 키는 화면 시연용이며 실제 사용에는 부적합한 길이입니다. 개인키를 붙여넣어도 전송되지는 않지만, 운영 키는 가급적 외부 도구에 넣지 않는 것이 원칙입니다.

자주 묻는 질문

BER이나 CER로 인코딩된 데이터도 되나요?
DER을 전제로 해석합니다. 길이를 정하지 않는 부정길이 인코딩 같은 BER 고유 형식은 오류가 나거나 잘못 해석될 수 있습니다.
인증서 내용을 사람이 읽기 좋게 보려면요?
주체, 발급자, 유효기간, SAN 같은 필드를 정리해서 보려면 같은 카테고리의 인증서 해석 도구가 더 편합니다. 이 도구는 바이트 구조를 확인할 때 씁니다.
