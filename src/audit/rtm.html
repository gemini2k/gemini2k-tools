요구사항 추적표 (RTM)

요구사항이 설계·구현·시험까지 빠짐없이 연결됐는지 추적합니다.

입력 내용은 이 브라우저에만 저장됩니다(전송 없음). 시험케이스가 비면 추적 누락으로 점검하세요.

요구사항 추적표(RTM) 사용 안내

무엇을 하는 도구인가

요구사항 추적표(Requirements Traceability Matrix)는 요구사항 하나하나가 어느 설계서에 반영되고, 어떤 프로그램으로 구현되고, 어떤 시험케이스로 검증됐는지를 한 줄로 이어 보는 표입니다. 이 도구는 요구사항 ID·요구사항명·유형·중요도·설계서·구현·시험케이스·상태를 기록하고, 완료율과 시험케이스가 연결되지 않은 건수를 자동으로 집계합니다.

언제 쓰나

  • 설계 단계 종료 시 모든 요구사항이 설계서에 반영됐는지 대조할 때
  • 통합시험 계획을 세우며 시험케이스가 빠진 요구사항을 찾을 때
  • 정보시스템 감리에서 요구사항의 단계별 추적성을 점검할 때
  • 검수 직전 "제안요청서 요구사항이 모두 구현·시험됐는가"를 증빙할 때

사용 방법

  1. "행 추가"로 줄을 만들고 요구사항 ID(예: REQ-001)와 요구사항명을 적습니다. ID는 요구사항 정의서와 같은 체계를 쓰세요.
  2. 유형(기능·비기능·데이터·인터페이스·보안)과 중요도(상·중·하)를 고릅니다.
  3. "설계서"에 문서명과 절 번호(예: 화면설계서 3.1), "구현"에 클래스·화면 ID, "시험케이스"에 TC 번호를 적습니다.
  4. 상태를 미착수·진행·완료·보류 중에서 갱신하고, 필요할 때 "CSV"로 내려받습니다.

결과 해석

요약줄은 "완료 비율%(완료/전체) · 시험케이스 미연결 n건"입니다. 완료율은 상태가 "완료"인 행의 비율이고, 미연결은 시험케이스 칸이 비어 있는 행의 수입니다.

기본 예시는 2건 중 1건 완료라 50%, 응답시간 요구사항(REQ-002)에 시험케이스가 없어 미연결 1건으로 나옵니다. 이 경우 성능시험 시나리오를 만들어 TC 번호를 채워야 추적이 완성됩니다. 미연결이 0이 아닌 채로 시험을 종료하면 검증되지 않은 요구사항이 남는다는 뜻입니다.

주의할 점

  • 미연결 집계는 시험케이스 칸만 봅니다. 설계서·구현 칸이 비었는지는 직접 확인해야 합니다.
  • 적힌 문서명이나 TC 번호가 실제로 존재하는지, 내용이 맞는지는 검증하지 않습니다. 형식상 연결과 실질 검증은 별개입니다.
  • 하나의 요구사항에 TC가 여러 개면 한 칸에 쉼표로 함께 적으세요.
  • 데이터는 이 브라우저에만 저장됩니다.

자주 묻는 질문

요구사항이 수백 건이면 여기서 관리할 만한가요?
초기 정리나 감리 대조용으로는 충분하지만, 장기 관리는 엑셀이나 형상관리 도구가 낫습니다. CSV로 내려받아 옮기면 됩니다.
"보류" 건은 완료율에 어떻게 반영되나요?
보류도 전체 건수에는 포함되므로 완료율을 낮춥니다. 범위에서 공식 제외된 요구사항이라면 별도 목록으로 분리해 관리하세요.
