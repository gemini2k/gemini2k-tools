테스트케이스·결함 관리대장

테스트케이스와 결함을 기록하고 수행률·통과율을 집계합니다.

결과가 Fail이면 결함ID를 연결하세요. 수행률·통과율이 자동 계산됩니다. 데이터는 브라우저에만 저장됩니다.

테스트케이스·결함 관리대장 사용 안내

무엇을 하는 도구인가

시험을 몇 건 했고 몇 건이 통과했는지, 실패한 건은 어떤 결함으로 등록됐는지를 한 표에서 관리하는 도구입니다. TC-ID, 기능/모듈, 시나리오, 입력/조건, 기대결과, 결과, 결함ID, 비고를 적으면 수행 건수와 통과율이 자동으로 집계됩니다. 결과는 미수행·Pass·Fail·Block·N/A 다섯 가지 중에서 고릅니다.

언제 쓰나

  • 단위·통합시험 기간에 매일 진척과 통과율을 보고해야 할 때
  • 사용자 인수시험(UAT)에서 현업 담당자가 시나리오별 결과를 직접 기록할 때
  • 감리 시 시험 수행 결과와 결함 조치 연결이 기록돼 있는지 확인할 때
  • 유지보수 배포 전 회귀시험 목록을 빠르게 돌려 볼 때

사용 방법

  1. "행 추가"로 테스트케이스를 만들고 TC-ID와 기능/모듈을 적습니다.
  2. 시나리오, 입력/조건, 기대결과를 다른 사람이 읽고 그대로 재현할 수 있을 만큼 구체적으로 씁니다. "로그인 확인"보다 "비밀번호 5회 오류 후 계정 잠금 메시지 표시"가 좋습니다.
  3. 시험 후 결과를 고르고, Fail이면 결함관리 시스템의 번호를 결함ID에 연결합니다.
  4. 입력은 자동 저장되며 "CSV"로 시험결과서에 첨부합니다.

결과 해석

요약줄은 "통과율% · 수행 n/전체 · Pass p · Fail f"입니다. 수행은 결과가 미수행이 아닌 건(Pass·Fail·Block·N/A 포함)의 수이고, 통과율은 Pass ÷ (Pass + Fail) × 100입니다. Block과 N/A는 통과율 계산에서 빠집니다.

예를 들어 전체 50건 중 Pass 36, Fail 4, Block 3, N/A 2, 미수행 5라면 수행은 45/50, 통과율은 36 ÷ 40 = 90%입니다. 통과율이 높아 보여도 Block 3건은 선행 결함이나 환경 문제로 시험 자체를 못 한 것이니, 원인을 풀고 재시험해야 시험 완료로 볼 수 있습니다. 기본 예시(Pass 1, Fail 1)는 통과율 50%로 표시됩니다.

주의할 점

  • Fail인데 결함ID가 비어 있어도 경고하지 않습니다. 종료 전에 결과 열과 결함ID 열을 함께 훑어보세요.
  • 같은 케이스를 여러 차수로 재시험한 이력은 남지 않습니다. 차수별 기록이 필요하면 차수마다 CSV를 저장하거나 TC-ID에 차수를 붙이세요.
  • 결함의 심각도·조치 상태는 관리하지 않으니 결함 자체는 별도 대장에서 관리합니다.
  • 데이터는 이 브라우저에만 저장됩니다.

자주 묻는 질문

Block과 N/A는 언제 쓰나요?
Block은 시험하려 했지만 다른 결함이나 환경 문제로 진행할 수 없을 때, N/A는 이번 범위에 해당하지 않아 시험하지 않기로 한 경우에 씁니다.
통과율이 몇 %면 시험을 끝내도 되나요?
정해진 값은 없고 시험계획서의 종료 기준을 따릅니다. 흔히 통과율과 함께 "치명 결함 미조치 0건" 같은 조건을 함께 둡니다.
