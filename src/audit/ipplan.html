IP 주소계획·서브넷 분할

네트워크를 N개 서브넷으로 분할해 주소계획을 만듭니다.

기준 CIDR을 2의 거듭제곱 개수로 균등 분할(FLSM)합니다. 모든 계산은 브라우저에서만 이루어집니다.

IP 주소계획·서브넷 분할 사용 안내

무엇을 하는 도구인가

하나의 네트워크 대역(CIDR)을 같은 크기의 서브넷 2·4·8·16·32개로 나누고, 서브넷마다 네트워크 주소, 사용 가능한 호스트 범위, 브로드캐스트 주소, 호스트 수를 표로 보여 줍니다. 모든 서브넷의 크기가 같은 고정 길이 서브넷 마스크(FLSM) 방식입니다. 서브넷 수가 2배가 될 때마다 프리픽스가 1비트씩 늘어나는 계산을 손으로 하다 실수하는 일을 막아 줍니다.

언제 쓰나

  • 신규 구축 사업에서 할당받은 대역을 DMZ·업무망·DB망·관리망처럼 구역별로 나눌 때
  • 네트워크 설계서의 IP 할당표가 겹치거나 경계가 틀리지 않았는지 검토할 때
  • 망분리나 VLAN 재구성 전에 구역당 몇 대까지 수용할 수 있는지 미리 볼 때
  • 클라우드 VPC 안에서 서브넷 대역을 균등하게 잡을 때

사용 방법

  1. '기준 네트워크'에 IPv4 주소를, 옆의 / 칸에 프리픽스 길이(0~30)를 입력합니다.
  2. '서브넷 수'에서 나눌 개수를 고릅니다. 값을 바꾸면 결과가 바로 다시 계산됩니다.
  3. 위쪽 요약에서 새 프리픽스, 서브넷당 호스트 수, 서브넷 마스크를 확인하고 표를 설계서에 옮깁니다.

결과 해석

기본값 192.168.0.0/24를 4개로 나누면 2비트가 늘어 /26이 되고, 서브넷 하나에 주소 64개, 마스크는 255.255.255.192입니다. 첫 서브넷은 192.168.0.0/26으로 호스트 범위 192.168.0.1 ~ 192.168.0.62, 브로드캐스트 192.168.0.63이고, 다음 서브넷은 192.168.0.64/26에서 시작합니다. 호스트 수는 네트워크 주소와 브로드캐스트 주소를 뺀 62개입니다. 실제로는 여기서 게이트웨이(보통 첫 주소)와 이중화 장비용 주소를 또 빼고 계획해야 합니다. 기준 주소를 192.168.0.77처럼 대역 중간 주소로 넣어도 프리픽스에 맞춰 192.168.0.0으로 내림해서 계산합니다.

주의할 점

모든 서브넷을 같은 크기로만 나눕니다. 서버망은 크게, 관리망은 작게 잡는 가변 길이(VLSM) 설계나 IPv6는 지원하지 않습니다. 분할 결과 프리픽스가 /30을 넘으면 오류를 표시하므로 /31·/32 대역은 다룰 수 없습니다. 사설 대역 여부, 기존 대역과의 충돌, 라우팅 요약 가능성은 검사하지 않으니 기관의 IP 관리대장과 대조하는 절차는 따로 거쳐야 합니다.

자주 묻는 질문

서브넷을 3개나 5개로 나눌 수는 없나요?
균등 분할은 2의 거듭제곱 개수만 가능합니다. 3개 구역이 필요하면 4개로 나눈 뒤 하나를 예비로 남기거나, 큰 구역 하나와 작은 구역 둘로 나누는 VLSM 방식으로 직접 설계해야 합니다.
클라우드에서도 호스트 수가 이대로인가요?
주요 클라우드는 서브넷마다 몇 개 주소를 자체 용도로 예약하기 때문에 실제로 쓸 수 있는 주소는 표의 호스트 수보다 적습니다. 사용하는 서비스의 문서에서 예약 개수를 확인하세요.
