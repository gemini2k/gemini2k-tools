SW 보안약점 자가점검

행안부 SW 개발보안 가이드 기준 보안약점을 유형별로 점검합니다.

행정안전부 「소프트웨어 개발보안 가이드」 7개 유형 대표 항목입니다. 충족률이 자동 집계되며 CSV로 진단보고서에 첨부하세요.

SW 보안약점 자가점검 사용 안내

무엇을 하는 도구인가

행정안전부 「소프트웨어 개발보안 가이드」는 보안약점을 입력데이터 검증 및 표현, 보안기능, 시간 및 상태, 에러처리, 코드오류, 캡슐화, API 오용의 7개 유형으로 나눕니다. 이 도구는 유형별 대표 항목 25개를 체크리스트로 묶어, 항목마다 충족·미충족·해당없음을 고르고 비고를 적으면 충족률을 자동 집계합니다. 가이드의 전체 항목을 모두 담은 것이 아니라, 개발 현장에서 자주 문제가 되는 대표 항목을 추린 자가점검표입니다.

언제 쓰나

  • 개발 단계 중간에 수행사가 스스로 보안약점 조치 상태를 점검할 때
  • 보안약점 진단을 받기 전에 미조치 항목을 미리 찾아 일정에 반영할 때
  • 감리에서 개발보안 적용 계획과 실제 구현 수준을 항목별로 대조할 때
  • 유지관리 중 기능을 추가한 뒤, 해당 모듈만 다시 점검할 때

사용 방법

  1. 유형별 항목을 읽고 충족·미충족·해당없음 중 하나를 고릅니다. 예를 들어 파일 업로드 기능이 아예 없다면 "위험한 형식 파일 업로드 제한"은 해당없음입니다.
  2. 오른쪽 비고 칸에 근거를 적습니다(예: "MyBatis #{} 바인딩 전수 적용, ${} 0건 확인").
  3. 선택과 비고는 자동 저장됩니다. 상단의 충족률을 확인하고 "CSV" 버튼으로 그룹·점검항목·결과·비고를 내려받아 보고서에 첨부합니다.

결과 해석

충족률 = 충족 ÷ (전체 − 해당없음) × 100이며, 반올림해 정수로 표시합니다. 표시 형식은 "82% 충족 (18/22 · 해당없음 3 · 전체 25)"입니다. 이 예는 25개 중 3개가 해당없음이라 분모가 22가 되고, 그중 18개가 충족된 경우입니다. 아직 고르지 않은 항목은 미충족과 마찬가지로 분모에는 들어가고 충족에는 들어가지 않으므로, 점검을 덜 했으면 충족률이 낮게 나옵니다.

충족률보다 중요한 것은 미충족 항목의 내용입니다. SQL 삽입이나 인증 없는 중요기능처럼 한 건만 있어도 사고로 이어지는 항목이 미충족이라면, 충족률이 90%여도 운영 반영을 미뤄야 합니다.

주의할 점

  • 자가 점검표일 뿐 코드를 직접 분석하지 않습니다. 공식 보안약점 진단(진단 도구와 진단원 검토)을 대신할 수 없습니다.
  • "충족"은 작성자의 판단입니다. 비고에 근거(설정 파일, 공통 모듈명, 진단 결과 번호)를 남겨야 제3자가 검증할 수 있습니다.
  • 데이터는 이 브라우저에만 저장됩니다. 선택과 비고는 화면 언어와 관계없이 같은 항목에 저장되므로 점검 도중 언어를 바꿔도 그대로 보입니다. 다만 CSV의 그룹·점검항목 이름은 내려받을 때의 화면 언어로 나옵니다.

자주 묻는 질문

해당없음을 많이 고르면 충족률이 올라가지 않나요?
분모가 줄어드니 올라갑니다. 그래서 해당없음에는 반드시 비고로 이유(기능 없음, 외부 솔루션 담당 등)를 적어 두는 것이 좋습니다.
가이드의 다른 항목은 어떻게 점검하나요?
여기 없는 항목은 가이드 원문 목록을 기준으로 별도 표를 만들어 보완하세요. 이 도구는 대표 항목 중심의 빠른 점검용입니다.
