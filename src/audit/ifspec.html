인터페이스(I/F) 정의서

시스템 간 연계 인터페이스 명세를 정리합니다.

연계방식(EAI/ESB/API/FEP/파일)·주기·전문형식·보안(암호화·인증)을 명확히 하세요. 데이터는 브라우저에만 저장됩니다.

인터페이스(I/F) 정의서 사용 안내

무엇을 하는 도구인가

시스템 간 연계 목록을 표로 작성하는 관리대장입니다. 인터페이스마다 I/F ID, 인터페이스명, 송신 시스템, 수신 시스템, 연계방식, 주기, 데이터형식, 보안 여덟 칸을 채웁니다. 연계방식은 API(REST), API(SOAP), EAI/ESB, FEP, 파일(FTP), DB링크, 메시지큐 중에서, 주기는 실시간·준실시간·시간·일·주·월·수시 중에서, 데이터형식은 JSON·XML·고정길이·CSV·기타 중에서 고르게 되어 있어 사람마다 표현이 달라지는 일을 줄여 줍니다. 상세 전문 레이아웃(필드별 길이·타입)까지 담는 문서가 아니라, 전체 연계 현황을 한 장으로 보여 주는 목록용입니다.

언제 쓰나

  • 분석·설계 단계에서 대내외 연계 대상을 빠짐없이 뽑아 인터페이스 목록 초안을 만들 때
  • 감리에서 연계 대상별 방식·주기·보안 대책이 설계서에 정해져 있는지 확인할 때
  • 통합시험 계획을 세우면서 연계 시험 대상과 상대 기관 일정을 정리할 때
  • 시스템 전환이나 폐기 전에 어떤 시스템이 이 시스템에 기대고 있는지 파악할 때

사용 방법

  1. 예시 행(IF-001 회원정보 연계, 포털 → CRM)을 참고해 [+ 행 추가]로 인터페이스를 하나씩 등록합니다.
  2. I/F ID는 IF-001처럼 일련번호 규칙을 정해 두고, 이 번호를 설계서·시험케이스에서도 그대로 씁니다.
  3. 송신·수신에는 시스템명을, 보안 칸에는 "TLS, API Key", "전문 암호화(SEED), 전용회선"처럼 실제 적용 대책을 적습니다.
  4. 입력은 자동 저장되며 [⬇️ CSV]로 내려받아 인터페이스 정의서 양식에 붙입니다.

결과 해석

이 도구는 점수를 매기지 않습니다. 완성된 표를 볼 때는 세 가지를 확인합니다. 첫째, 보안 칸이 비어 있는 행입니다. 특히 개인정보가 오가는 연계인데 전송 구간 암호화가 적혀 있지 않다면 설계 보완 대상입니다. 둘째, 주기가 '실시간'인데 연계방식이 파일(FTP)처럼 맞지 않는 조합입니다. 셋째, 송신과 수신이 같은 시스템 쌍인데 ID가 여러 개로 흩어진 경우로, 통합하거나 용도를 구분해 적어야 합니다.

주의할 점

입력값의 형식이나 논리를 자동 검증하지 않습니다. 보안 칸은 자유 입력이라 "적용"처럼 막연하게 적어도 그대로 저장되니, 암호화 알고리즘·인증 방식·전송 구간을 구체적으로 쓰는 습관이 필요합니다. 데이터는 이 브라우저에만 저장되므로 여러 사람이 함께 쓰는 공식 정의서는 CSV로 내보내 형상관리 대상 문서로 관리하세요.

자주 묻는 질문

필드 단위 전문 명세도 여기 적나요?
여기서는 인터페이스 단위 목록만 관리하고, 필드명·길이·타입·필수 여부 같은 전문 레이아웃은 I/F ID별 상세 명세서로 따로 만드는 것이 보통입니다. 이 표의 ID가 두 문서를 잇는 열쇠가 됩니다.
양방향 연계는 어떻게 적나요?
요청과 응답이 한 거래 안에서 끝나는 API라면 한 행으로 적어도 됩니다. A가 B에 보내고 B가 별도로 결과를 회신하는 구조라면 송신·수신을 바꿔 두 행으로 나눠야 시험과 장애 추적이 쉬워집니다.
